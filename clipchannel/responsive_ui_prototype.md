# 作業別UIの比較試作

問い：5つの作業分類、手動切替、サイズ別の操作到達性、役割別配色、詳細設定と処理状態・中止の配置を比較する。

本番はTkinter。試作は隣接する独立HTMLと標準ライブラリの専用サーバーであり、本番モジュールを読み込まない。すべて架空データとメモリ内状態で、実ファイルの取得・登録・保存・削除・外部編集を実行しない。

## 起動

リポジトリのルートで `python clipchannel/responsive_ui_prototype.py`。
WindowsからWSLのPythonを使う場合は `wsl python3 clipchannel/responsive_ui_prototype.py`。

http://127.0.0.1:8765/prototype/responsive-ui?variant=A

下部の矢印、または左右キーで比較。入力欄・選択欄・ダイアログ操作中は左右キーを奪わない。

| 案 | 配置 | 色と状態表示 |
|---|---|---|
| A | 上部5作業タブ、操作と結果を並置 | 明るい中性背景、標準青、下部に処理状態 |
| B | 左ナビ、縦に続くフォームと結果 | 白中心、濃い青、ヘッダー直下に処理状態 |
| C | 工程リストと明示的な作業選択、広めのプレビュー | 淡い青背景、青の境界、下部に処理状態 |

どの案も作業ごとの色分けはしない。青＝主要操作、赤＝注意操作、緑＝成功、黄＝警告。選択表示・文字ラベルと組み合わせる。

## 確認手順

1. 初期の中サイズ・動画を準備でURLを変更し、案・作業・タブ・サイズを往復して入力保持を確認する。
2. 5作業すべてと8タブを回る。150%・小では左ナビもスクロールできる。
3. 詳細設定値を変更して折りたたみ、再度開く。処理状態を失敗にすると詳細設定が開く。
4. 処理を開始し、別作業へ移動して中止する。完了時は画面を維持し、次の作業への案内を表示する。
5. 空、長いパス・本文、処理中、失敗を選び、スクロールで操作に到達する。
6. 画面・字幕と補助素材のプレビュー、削除確認、保存・書き出し設定を開き、全体表示と取消・確認操作を比べる。

## 検証と限界

3案×100/125/150%×小/中/大の27条件で、本文のスクロール領域が残り中止ボタンがアプリ領域内にあることをブラウザで確認。150%・小・長文の目視確認で左ナビ末尾が隠れる問題を発見し、独立したスクロールを追加した。案切替時のURL入力保持、5番目の作業への移動、失敗時の詳細展開も確認した。

表示倍率は1920×1040の利用可能な領域を仮定してCSS寸法に換算した模擬表示。Windows実機でのDPI保証やTkinterでの成立確認ではない。ブラウザが狭い場合、試作の外側にもスクロールが発生する。

既存操作の代表例を配置した比較用画面であり、本番全入力の移植・保存規則の実装ではない。前回作業・サイズ復元、最大化解除、画面条件変更時の補正は本番仕様として維持し、この永続化しない試作では未検証。詳細エラーは比較用の模擬設定エラー。

結論：比較用試作は作成済み。採用案・組み合わせの利用者評価は未確定。本番への反映はしていない。
