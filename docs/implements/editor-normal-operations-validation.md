# AviUtl2の保存・再読込み・Undo/Redoの通常操作

A107後の継続検証。A105と同じ分離済みAviUtl2 2.1.9、exe隣のdataフォルダによる設定分離を使用。利用者の既存プロジェクトは開いていない。追加プラグイン・アプリ側連携コードは未導入。

## 実施したこと

1. 空のRootシーンのLayer1へ、標準のテキストオブジェクトを1個追加。本文は空のまま。
2. Ctrl+Zでタイムラインから消えること、Ctrl+Shift+Zで同じ位置に戻ることを画面で確認。
3. Ctrl+Sから新規ファイルnormal-operations.aup2を分離フォルダへ保存。ファイルの存在・内容を確認した。
4. 新規プロジェクトを作って空のタイムラインへ切り替え、保存したファイルを開き直した。Layer1のテキストオブジェクトと全体140フレームの表示が戻った。
5. 保存済みプロジェクトを変更せずエディターを通常終了し、対象ウィンドウがなくなったことを確認。

保存ファイルは1,381 bytes、SHA256 `01B1A5C8905FECF05F88D9D02D50D0827E2CD8A559910BF676D89E18451EB7B0`。内容は1920×1080、30fps、44.1kHz、layer=0、frame=59,139、effect.name=テキスト、空の本文、標準描画。画面観測と保存ファイルを組み合わせた確認であり、タイトルの保存済み表示だけで判断していない。

[保存した検証ファイル](evidence/editor-normal/normal-operations.aup2)。ファイル内に検証時の絶対パスを含む。任意の場所へ配置した際のパス補正や互換性は未検証。

## 操作ツールで見つかった制約

保存ダイアログはアクセシビリティ上のフォーカスが検索欄を示す一方、画面のカーソルはファイル名欄にあり、要素IDを使ったset_valueはキャッシュ無効エラーとなった。画面を再観測し、実際の入力欄へパスが入ったことを確認して保存した。新規作成ダイアログではReturnで確定せず、観測したOKボタンの座標クリックで確定した。

したがって、今回のComputer Useによる通常操作が成立しても、そのまま安定した製品連携方式とはしない。対象ダイアログ・フォーカス・完了状態の識別が引き続き必要。

## 判定

E2は単一の本文空オブジェクトの保存・再読込みを部分確認。E3は標準オブジェクト追加のUndo/Redoを画面上で部分確認。字幕本文、複製後の独立編集、BGM・効果、アプリ保存世代、専用プラグインの状態照合は未検証。画面が同じ位置へ戻ったことを全状態の一致とは扱わない。

E4の編集排他・出力、E5の未保存状態を含む復元は未実施。既存の模擬失敗枠を消化していない。ADR-0003の成立未確認操作を実行停止する条件、ADR-0005のプラグイン方針を維持する。本体実装・仕様確定・Issue分割は行っていない。
