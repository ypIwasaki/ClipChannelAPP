# A107後の発話検出・ASR最小検証

対象はA107で本人のみと確認された2本の20秒区間。仕様確定・本体実装ではなく、固定候補のWindows CPU実証。

## 条件

- VAD: Silero VAD6.2.2、パッケージ内JIT重み。threshold=0.5、最短発話250ms、最短無音100ms、前後余白30ms、16kHz。製品初期値の決定ではない。
- 話者: A107の保存済み192次元特徴と、各VAD区間のECAPA特徴をcosine比較。人物判定の閾値は設定せず、対象者の正解はA107による。
- ASR: 分離venv、faster-whisper1.2.1、CTranslate2 4.8.2、CPU int8、4スレッド、large-v3のrevision `edaa852ec7e145841d8ffdb056a99866b5f0a478`。日本語指定、beam_size=5、temperature=0、前区間テキストの引継ぎなし、語時刻あり。推論時はローカルモデルとPython socket接続拒否を使用。
- 取得したASRモデルはローカルの `C:/Users/raimu/AppData/Local/ClipChannelAPP-validation/asr-probe/model`。GPU・ドライバ・システムPATHは変更していない。

Silero6.2.2はJIT方式でもパッケージimport時にsequence_vad経由でonnxruntimeを必要とした。初回はModuleNotFoundError、ONNX Runtime1.30.0の明示導入後に実行成功。通常のpip依存解決だけでは追加されなかった。torch/torchaudio2.8.0+cpuは維持し、導入後のpip checkは両環境とも成功。

## 発話検出で分かったこと

1本目03:00〜03:20は0区間、2本目07:00〜07:20は7区間。A107は話者についての利用者確認であり、連続して発話しているというサンプル単位の注釈ではない。無検出の理由や検出精度をこの結果だけで断定しない。1本目はVADによる除外をせず、20秒全体をASRへ渡す診断を追加した。この診断経路を製品の自動フォールバック仕様とはしない。

検出した2本目の短い区間ではcosineが約0.30〜0.74まで変動した。短区間・無発話・BGMの影響を未分離なので、既定の二値閾値をそのままアプリの対象者判定へ使う根拠は得られていない。

検証コード: [VADと照合](evidence/a106/vad_probe.py)、[ASR](evidence/a106/asr_probe.py)。処理結果の正解テキスト比較や、人による修正操作の確認はまだ含まない。

## 実測結果と判断

7つのVAD区間と、無検出だった1本目全体の診断、計8入力のASRが成功。モデル読込みから終了まで93.20秒（単回、CPU4スレッド）。結果セグメントの相対開始・終了が入力区間内（末端0.1秒の検査許容）にあることをコードで確認し、元動画オフセットを加えた時刻を保存。音声に対する発語時刻の正確さや正解文との一致は未評価。

1本目の全体ASRではテキストが生成された。無検出を無発話の証明にできない具体例である。ただしASR出力自体も正解証拠ではない。VAD設定の感度を0.5/0.3/0.1の3点だけ比較すると、1本目は0/0/1区間（最後でも3.356秒）、2本目は7/7/1区間（15.236/16.454/19.998秒）。閾値を下げれば問題が解消するとは結論しない。製品の閾値変更は未決定。

A49/A50の不明保持・時刻付き発言追加を維持し、VAD無検出を自動的な対象話者の非発話確定や素材削除へ結びつけない。これは新しい自動再試行機能の合意ではない。

S3は本人のみの実素材でVAD→特徴照合→ASRの実行入口を部分確認。他者排除・重なり・判定閾値・手修正UIは未検証。S4の長尺・中止、S5移行、S6GPUも未実証。現段階で仕様全体の完了や編集機能の成立とはしない。
