# 保存・引き継ぎ・完成確認の検討案

> 保存形式の追加合意（2026-09-24）：解析結果と人物・登録語・除外語などの共通設定はCSV。初版のSQLite候補は取り下げる。参照音声・人物特徴などの実体ファイルはCSVに変換せず別保存する。

> 解析結果の保存階層（2026-09-24）：`catalog/<元動画名>/` の下に文字起こし・区間一覧・頻出語集計の種類別フォルダを置き、各結果を `<元動画名>_vN` のファイルとして保存する。解析結果のDB管理候補はこの合意で取り下げ、後続合意で人物・共通設定もCSVに決定し、初版のDB候補はなくなった。

> 最新の移動範囲（2026-09-24）：同一PC内のデータ用フォルダ複製・取り込みも初版から外す。利用者が既存フォルダを指定して使用先を切り替える操作は残す。別PC引き継ぎも対象外。以下のパッケージ内容・移行検証は旧案と実証履歴であり、初版の必須範囲ではない。

> 同名動画の追加合意（2026-09-24）：同じデータ用フォルダで別動画の元ファイル名が既存動画と重なる場合は警告し、名前変更まで新規登録・解析を止める。既存動画の再解析は `_vN` を進める。

> 参照の追加合意（2026-09-24）：編集用動画・補助素材は利用者が利用時にアプリから選ぶ。参照音声・人物データの移動後参照も初版では保持しない。解析結果は元動画1本ごとに作り、複数動画を一結果へまとめない。同名の別動画による結果ファイル名の衝突は別問題として残す。以下の自動再接続・参照パス保持は旧案とする。

> 引き継ぎ範囲の追加合意（2026-09-24）：別PCへの作業データ引き継ぎは初版から外す。同一PCの別データ用フォルダへの取り込み・切り替えは維持する。以下の別PC向けパッケージ内容・互換性・編集プロジェクト同梱の記述は旧案として扱い、初版の移動方式はDB範囲縮小に合わせて再設計する。

> 最新合意（2026-09-24、[ADR-0009](../adr/0009-limit-database-to-speaker-and-analysis.md)）：初版のDB管理から素材・編集・処理と出力を外し、編集データの復旧機能も初版から外す。以下の広範なSQLite台帳、編集と処理のDB登録・復旧、引き継ぎ時のDB参照に関する記述は旧提案・検証記録であり、初版の採用案ではない。後続合意によりこれらも含め初版の情報保存はCSVと通常ファイルとし、SQLite候補は取り下げた。引き継ぎ機能も初版から外した。

後続合意A87・88: 初版のデータ用フォルダはWindowsから直接使う内蔵・外付けドライブを対象とし、NAS・ネットワーク共有・クラウド同期中のフォルダは対象外。引き継ぎ書き出しは実行中処理・未保存入力を解消してから開始し、完了・中止までデータ変更を待つ。以下の関連する未合意表記はこの回答で更新されるが、SQLite・ZIP64・7z等の内部方式はまだ提案である。A89で参照音声・人物データを同梱し、アプリ・外部ツール・共通の認識モデルは移行先で別途準備すると合意。A90で依存物未準備でもデータ取り込みと保存済み情報閲覧は可能にし、依存物が必要な処理だけを止めると合意。形式・整合性の検査は維持する。

2026-09-18、A84までの合意に基づく設計案。2026-09-24にデータ用フォルダの最上位階層と編集ごとの下位フォルダ配置は利用者が承認した。SQLite・ZIP64・7z等の内部方式は採用決定・実装計画・Issue分割ではない。DB・アーカイブを実際に作成したり、実データを移行したりしていない。原本 `spec-legacy-v0.1.md` は保持する。

## 旧方式の提案と検証履歴

以下のSQLite全域管理・ZIP64移行案は初版の現行設計ではない。フォルダ階層と動画保管の合意は有効だが、移行パッケージの内容やDB複製の手順を初版の完成条件にしない。

- データ用フォルダごとにSQLiteを1つ持ち、アプリの保存担当だけがDBを書き換える。動画・音声・人物モデルは通常ファイルとして別に置く。
- Windows側の保存担当を基準案とする。WSLを使う場合もWSLの処理から同じDBを直接開かず、処理結果を保存担当へ返す。
- 引き継ぎはZIP64対応の単一パッケージに、整合したDBの複製、参照音声、人物モデル・特徴データ、内容一覧と版情報を格納する。
- 取り込みは新しい別フォルダに行い、既存環境を置換しない。人物データの互換性を、ファイルを運べることと区別して確認する。
- 動画の可逆保管は7zを比較の第一候補とする。引き継ぎパッケージと動画アーカイブは異なる成果物として扱う。
- 完成確認は原本ACと会話の変更を対応付け、成功・中止などの通常確認と、上限3件の模擬失敗を分ける。

## 一次資料で確認したこと

| 確認事項 | 根拠 | このアプリへの含意（設計判断） |
| --- | --- | --- |

| 7zはLZMA/LZMA2等、Unicode名、大きいファイルを扱う。利用条件は構成要素によって異なる。 | [7z format](https://www.7-zip.org/7z.html)、[license](https://www.7-zip.org/license.txt) | 可逆保管の候補。MP4の容量削減率は未保証。採用版・実行物の依存・許諾は固定前に確認する。 |

## データ用フォルダと保存担当

下表の最上位フォルダ階層は2026-09-24に利用者が承認した。利用者向けUIに内部構造の理解を要求しない。各領域の内部ファイル形式や引き継ぎパッケージへの同梱方法は別の判断である。

| 領域 | 保持内容 | 引き継ぎパッケージ |
| --- | --- | --- |
| `catalog/` | 人物・共通設定のCSVと、元動画名・結果種類・版ごとの解析結果CSV | 複製・取り込みパッケージは初版対象外 |
| `media/` | 取得元ファイル、変換後動画、編集用動画、クリップ、画像・BGM・効果音、音声成果物 | 実ファイルは別途移動。参照情報は含む |
| `people/` | 登録済み参照音声、作成した人物モデル・特徴データ、処理条件 | A29・66に従い実体を含む |
| `projects/` | 明示保存した編集プロジェクト。初版は利用者が直接選んで開く | 引き継ぎパッケージは初版対象外 |
| `exports/` | 完成動画 | 実ファイルは別途移動。参照情報は含む |
| `archives/` | 動画の可逆アーカイブ | 実ファイルは別途移動。参照情報は含む |
| `work/`・`recovery/` | 処理単位の作業領域と復元用情報 | 含めない。復元用情報は未完成物と一緒に削除しない |
| `logs/` | 秘密情報を除いた処理記録 | 通常の移行対象から外す案 |

2026-09-24の追加合意では、編集用MP4は元動画1本の画質を上限とし、区間のアルファベットと数字を使用順に「_」で区切ったファイル名にする。編集ごとに別フォルダを使い、同名で再生成しても旧動画・旧AviUtl2プロジェクトを残す。採用した下位配置は、編集用動画を `media/edits/<編集フォルダ>/A1_B2_C3.mp4`、対応する明示保存済みプロジェクトを `projects/<編集フォルダ>/` に置く方式。初版は過去の編集をアプリ内で選んで再開せず、利用者がAviUtl2プロジェクトを直接選んで開くため、両者の対応をアプリ側の台帳で管理しない。プロジェクトが参照する動画・補助素材が移動した場合は利用者がファイルを選んで対応し、初版のアプリによる自動再接続・参照先修正は行わない。フォルダの内部名はアプリが決め、利用者に識別子入力を求めない。編集フォルダの内部名・具体プロジェクトファイル名は実装時に決める。利用者が指定するのはデータ用フォルダである。

A95により動画取得の認証秘密値はアプリに永続保存せず、引き継ぎにも含めない。外部認証ファイルの参照先を記憶しても、移行先で使用可能な認証が準備済みとは扱わない。実行中の処理・未保存の入力・外部プログラムの実行物もパッケージに含めない。素材の取得元URL等に認証用の値が入り得るため、単に設定ファイルを除けば十分とはしない。登録時から永続保存可能な取得元情報と実行時の秘密情報を分け、移行時は対象項目を列挙して検査する。

A87により、実データはWindowsから直接使う内蔵・外付けドライブを対象とし、NAS・ネットワーク共有・クラウド同期中フォルダは対象外。SQLiteをWindows側の単一保存担当から扱う方式は提案のままである。開発用リポジトリの所在と実データの所在は別。

2026-09-24追加合意：解析結果のファイル名は元動画名（拡張子を除く）を流用し、初回から `_v1`、再解析ごとに `_v2` 以降を付ける。例：`sample.mp4` から `sample_v1`、再解析は `sample_v2`。結果の形式はCSVとし、列構成等は実装時に決める。別元動画の同名は登録時に止め、結果種類間は下記の種類別フォルダで分ける。これは素材をDBで管理する方針ではない。

初版の解析結果の下位配置は次のとおりとする。フォルダ名は結果の種類を示し、各結果はCSV形式とする。列構成・文字コード・時刻表現は実装時に固定する。

```text
catalog/
  <元動画名（拡張子なし）>/
    transcripts/
      <元動画名>_v1.csv
    segments/
      <元動画名>_v1.csv
    word-counts/
      <元動画名>_v1.csv
```

再解析では該当種類の次の `_vN` を作り、旧版を上書きしない。同名の別元動画は登録前に止める。複数種類の結果を同じ元動画フォルダに置いても、種類別フォルダで衝突しない。

## 保存情報の単位

| 単位 | 提案する区別 |
| --- | --- |
| 素材情報／素材ファイル | 安定した素材IDとファイルIDを分ける。ファイル不在でも情報・関係を残す。名前・保存パス・ハッシュだけを主キーにしない。 |
| 文字起こし結果／区間一覧／集計結果 | 再実行ごとに別ID。利用した素材・人物データ・辞書・入力結果の版を参照する。手修正で別の結果を暗黙に更新しない。 |
| 人物／人物データの版 | 名前と人物IDを分け、参照音声セット・作成方式・モデル版・特徴次元等の互換情報を持つ。再学習を既存モデルの無条件置換にしない案。 |
| クリップ／編集上の配置 | 同じクリップを複数配置でき、各配置の字幕・効果・選んだ補助素材を独立させる。配置削除をファイル削除へ連動させない。 |
| クリップへの紐づけ／補助素材の再生範囲 | 紐づけ先と相対開始、素材内の開始、再生長を区別。境界をまたぐBGMも表現する。 |
| 保存済み編集／復元用情報／Undo履歴 | A82の明示保存、失敗復元、A79の通常取消しを別の責務として扱う。SQLiteだけで外部編集を復元したとはしない。 |

時間は整数マイクロ秒による共通時刻に加え、元メディアのtime base・PTSと編集フレーム番号を保持する案。可変fpsの素材を平均fpsだけで時刻へ戻さない。区間は開始を含み終了を含まない範囲とする案で、端で接する発言の二重取込みを避ける。実際の切断フレームへの丸め規則は別途確認が必要。

タイトル・名前・本文・利用者が編集可能な時刻等と内部IDは分離し、任意SQLや任意内部IDの書換えを管理GUIへ追加しない。元動画情報の関連結果がある場合はA35どおり削除を止める。他の参照中情報の削除は、無条件の連鎖削除を避ける設計案を提示してから範囲を決める。

## DBとファイルをまとめて成功扱いにしない手順

1. 処理IDと出力予定先を記録し、その処理専用の作業領域へ新規出力する。入力や既存成果物を作業領域扱いしない。
2. 出力の存在・形式・必要ストリーム・読込可能性を確認し、確定予定のファイルと関係を準備する。
3. 既存ファイルと衝突する場合は合意済みの上書き確認に従う。旧成果物を保護したまま、新ファイルの確定とDB登録の段階を記録する。
4. DB登録まで完了して初めてアプリの利用可能結果にする。間で停止した場合は、記録から新生成物・旧成果物・未登録の完成物を判別する。自動で処理本体を再実行しない。

複数ファイルとDBをOS横断の単一トランザクションにできるとは仮定しない。置換前の旧ファイルを残す場所、確定順、再起動時の解決方法を実装前に状態遷移として詰める。所属が不明なファイルは削除しない。保存完了表示前に失敗した入力はアプリ動作中保持し、手動再試行できるようにする。

## 引き継ぎ形式の案

`manifest.json`、`catalog.sqlite`、`people/`、A93で追加した保存済み`projects/`の実体を持つZIP64パッケージ。manifestには形式版、スキーマ版、作成アプリ版、作成時刻、対象データ用フォルダの識別子、内容ファイルの相対パス・サイズ・SHA-256、必要ツール／モデル情報を記録する。ハッシュは偶発破損・取り違えの確認であり、発行元の認証ではない。

人物ごとに生成した重み・特徴はA66どおり含める。共通の巨大な基盤モデルは人物データと区別し、必要なモデルの版・ハッシュ・取得元を記録する案。A89によりアプリ・外部ツール・共通の認識モデルは移行先で別途準備し、完全なオフライン一式移行は初版要件にしない。基盤モデル取得条件が移行先で満たせない場合は、人物データだけで再利用可能と表示しない。

書き出しは未保存入力と実行処理を解消した状態で行い、DB snapshotと人物データの版を固定する案。コピー中に参照音声等が書き換わらないよう、完了まで変更を止める。この変更待ちはA88で合意済みであり、A63のフォルダ切替制限とは別の制約として扱う。中止要求だけで変更を再開しない。

取り込みは新規の一時フォルダで行う。絶対パス・親への脱出・重複名・リンク等を扱う規則を持ち、アーカイブ指定だけで既存の場所へ展開しない。manifest、同梱実体、DB整合性、外部キー、アプリの関係を確認してから新しいデータ用フォルダとして有効にする。失敗時は元フォルダと現在利用中の環境を変更しない。既存の編集や人物データへ自動統合しない。

新しい形式を古いアプリで開く場合は推測して書き換えない。旧形式の変換は元パッケージを保持したコピー上で実施し、変換結果と必要条件を表示する。人物モデルが移行先で使えなくてもDB・参照音声・人物情報は失わず、理由を示す。

別途移動するファイルは、管理フォルダ内の相対パスと内容指紋を再接続に使う案。候補検索ではサイズ等で絞り、同一性は内容照合で確認する。名前やURL一致だけでは自動接続しない。複数候補や内容変更は利用者が選び、重複登録はA36の選択を残す。

## 可逆圧縮の案

7z/LZMA2、動画ファイル単位のアーカイブを第一比較案にする。これにより一件の動画だけを明示的に展開でき、複数巨大動画を一つのsolid archiveへまとめる既定を避ける。形式の正式採用・設定値・配布版は未決。ZIP64は移行用として扱いやすい一方、可逆動画保管の容量効果とは別に比較する。

圧縮前のサイズ・ハッシュを記録し、完成したアーカイブを読んで元内容との一致を確認する案。展開先は利用者が選び、既存ファイルへの上書きは共通確認に従う。元動画、アーカイブ、展開物をそれぞれ保持し、容量が減らなかった場合もA65どおり保管・移送用として残す。具体的な既定の展開先は未決。

### 模擬失敗は3件を基本上限

| 件 | 隔離した模擬条件の案 | 確認する一つの保護条件 |
| --- | --- | --- |
| 1 | 新しい出力の確定前に、その処理だけ失敗を返す | 既存の正常出力と入力を保持し、当該処理の新規未完成物だけを扱う |
| 2 | 一件の本文または区間の確定保存時に、保存担当が失敗を返す | 入力が残り、手動再試行できる。両方へ機械的にケース追加しない |
| 3 | 以前の未保存編集を含む状態で、関連配置を変更する一つの編集を途中失敗とする | 当該変更だけを処理前へ復元し、以前の未保存編集を失わない |

これらの実装上の模擬方法は方式決定後に選ぶ。実ファイル破損、容量枯渇、通信遮断等で原因組合せを増やさない。失敗復元自体の失敗・強制停止等までこの3件で検証済みにしない。未検証として記録し、設計上の保護は維持する。実際の不具合に対する追加確認は理由と範囲を示す。

### 長時間・素材・終了判定

原本M01（約1時間）・M02（約7時間）の指定を維持する。現在は取得可否・実長・形式を実行確認しておらず、素材をダウンロードしていない。M03の短区間とM04の対象者／他者／重なり、M05の約10時間条件は準備が必要。M01・02の全工程全編を毎回繰り返す要求にはしない。10時間の実測を7時間の成功から推定しない。

集計・時刻・配置の期待結果は人が用意した小さな例で確認し、対象者素材の品質点数や全文修正量を合格基準に追加しない。時間・資源使用は記録し上限は設けない。進捗が取得できない場合は段階・稼働状態を示し、架空の進捗率を作らない。
