# 特殊な入力素材の初版対応案

> 最新範囲（2026-09-18）：既存2本の実取得に不要だった認証付き取得、HDR・用途別複数音声などの特殊入力、配布パッケージ・別環境での配布検証は初版から外す。[範囲判定と残す通常経路](initial-scope-pruning.md)を優先する。実行に必要なyt-dlp等、通常の変換・時刻対応、対象話者の照合は維持する。

2026-09-18、A101までの合意を前提に作成し、A102・103で複数音声の用途別選択とHDRのSDR変換・初版SDR出力に合意した。その他の提案と採用版の実証は別に扱う。原本は変更せず、実装・実行・素材取得は行っていない。[時刻・変換案](media-time-conversion-proposal.md)の必要時のみ別ファイルへ変換する方針、最近傍境界と差の表示、元ファイル保持を維持する。

## 一次資料で確認できる部品

- FFmpegは入力ストリームを番号で明示選択できる。自動選択では利用者が意図する話者・言語の音声になるとは限らないため、選択内容をアプリ側で保持する案とする。[FFmpeg Stream selection](https://ffmpeg.org/ffmpeg.html#Stream-selection)
- FFmpegには色変換の`zscale`と`tonemap`がある。`tonemap`は線形光での処理を前提とし、`zscale`はlibzimgを有効にしたビルドが必要。フィルター名が存在するだけで、採用するWindows配布物や色再現の確認が済んだとはしない。[FFmpeg tonemap](https://ffmpeg.org/ffmpeg-filters.html#tonemap)、[zscale](https://ffmpeg.org/ffmpeg-filters.html#zscale)
- YouTubeのHDR動画には10/12ビット、Rec.2020、PQまたはHLGなどの条件がある。合意済みのSDR初期値をそのままHDR対応の保証に転用できない。[YouTube HDR仕様](https://support.google.com/youtube/answer/7126552?hl=ja)
- AviUtl2の調査対象は本体2.1.9／SDK 2026-09-05。配布ページの公開と必要環境は確認できるが、この構成で複数音声の選択やHDR入出力が成立した証拠ではない。[AviUtl公式](https://spring-fragrance.mints.ne.jp/aviutl/)、[既存操作対応表](editor-integration-options.md)

## 複数音声トラック

**初版は、話者判定・文字起こし用と、完成動画に使う元音声用をそれぞれ1本選ぶ案を推奨する。** 同じ音声を両方に指定できる。例えば、マイク単独の音声で文字起こしし、ゲーム音入りの音声で完成動画を作る。話者を識別する処理と音声トラックの選択を混同しない。

選択画面では番号・言語・名称・チャンネル情報など取得できた情報と試聴を提供する。情報が欠けている場合は欠落を示し、名前や言語を推測で確定しない。音声が1本ならその1本を初期選択する。複数なら内容を確認して選ぶ。

元ファイル内の選択元と、変換結果内の選択先の対応を保存する。話者処理側で音声をモデル用に変換しても、完成動画側の音声をその低サンプルレート等へ置換しない。両方を共通の元動画時刻に対応付ける。トラック変更後の再処理は別の結果として保存し、既存文字起こし・字幕・区間を暗黙に置換しない。

この提案は「複数トラックを同時に混ぜる編集機能」を追加しない。既に合意している外部のBGM・効果音の追加は維持する。A102で用途別に各1本を選べる方式を初版に含めると合意した。

## HDR入力と完成動画

**初版は、HDR素材を保持し、SDRの編集用ファイルへ変換したプレビューを確認して編集・出力する案を推奨する。HDRの完成動画出力は後続検討とする。** この範囲はA103で合意済み。HDR出力は後続検討であり、後続版での実装を確約しない。

変換の理由、HDRからSDRへ変更すること、出力色設定を表示する。変換結果が元のHDR表示と同一であるとは説明しない。プレビュー確認は画質の利用者判断であり、単にプレビューが表示されたことを色管理全体の合格にしない。元ファイルは保持し、SDR版と区別して管理する。完成動画の合意済みSDR設定（A101）と整合する。

入力の色メタデータが不足・矛盾していて安全に変換条件を決められない場合は、自動的にSDRと見なさず理由を表示する。登録・保存済み情報の閲覧まで一括して禁止せず、正しい変換や編集が必要な処理を区別する。既存SDR素材を一律に変換し直す提案ではない。

HDR出力を初版必須とするなら、入力・プレビュー・効果・字幕合成・エンコード・メタデータの全経路が条件を満たす必要がある。現時点ではAviUtl2と採用候補プラグインで未実証。A85に従い別の編集基盤を用意せず、困難な場合は機能単位で再検討する。

## 音声のない動画

音声トラックがない動画は、登録・映像確認・手動の切り出し区間追加・編集を継続可能とする案。元音声はないまま扱い、合意済みのBGM・効果音を追加できる。音声が必要な話者判定・文字起こし・参照音声登録は理由を表示して実行対象外とする。

「音声が存在しない」と「ある音声を読み出せない」を区別する。読み出し失敗や未処理の区間を対象話者の非発話区間として自動確定しない。全編を架空の解析結果で埋めず、手動区間から映像作業を始められる案とする。映像側も読めない場合まで再生・編集できる保証はしない。この動作はA14・A17・A90との整合を図る提案で、成立未確認。

## 選択の履歴（A102・103で回答済み）

1. 複数音声がある動画では、話者処理用と完成動画用の音声を、それぞれ1本選べる方式を初版に含めるか。推奨は含める。同一音声を指定可能にする。

## 2026-09-18：用途別音声選択のFFmpeg部品検証

固定済みWindows FFmpeg9.0.1 essentialsで、2秒の合成映像と440Hz／880HzのPCM音声2トラックを持つMKVを作成した。`-map 0:a:0`を文字起こし用16kHz mono PCMへ、映像と`-map 0:a:1`を完成動画用MP4/H.264/AAC-LC 48kHzへ出力した。文字起こしモデルの推論は実行していない。

両出力をPCMとして確認し、内部1.5秒のゼロ交差計測でそれぞれ440.0Hzと879.33Hzだった。両音声は2秒で、完成MP4にはAAC-LC音声が1本のみ存在し、元MKVのSHA256は不変。各コマンド終了コード0。FFmpegの機能一覧にはlibx264、aac、zscale、tonemapが含まれていた。

証跡：`evidence/media-contract/multi-audio-probe.py`、`multi-audio-result.json`、各実行ログ。合成素材・出力は結果JSONに記したWindows一時フォルダに保持する。アプリの音声選択・試聴・保存UI、AviUtl2への選択音声受渡し、開始時刻の異なる音声は未確認。HDRフィルターの搭載確認であり、PQ/HLG変換の実行・色再現の評価は未実施。A102の部品成立を部分確認したが、A102/A103全体の合格や変換設定の正式採用とはしない。
