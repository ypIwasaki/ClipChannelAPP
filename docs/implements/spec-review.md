## 続けて確認する論点

- ローカル動画の取り込みが必要か。保存済み素材の再利用は明記されているが、アプリ外で入手した動画の初回登録経路は不明。
- 発話・非発話を全区間ファイル化する必要性。範囲だけを保存し、選んだ場面を出力する案との比較。
- 非発話の定義、未知区間、重なる区間、前後余白の重なり、字幕の元時刻から完成動画時刻への対応。
- ASRの再実行結果と手修正の識別、結果選択の負担、既存クリップがどの時点の情報を使ったか。
- 全CLI対応の目的と、GUIで各設定を操作する要求なのか追加引数入力でもよいのか。固定保護条件との優先関係。
- AviUtl2を優先する理由、実際に繰り返す編集操作、手編集とアプリ操作の同時変更、復元が失敗した場合の扱い。
- 圧縮の目的は容量削減・保管・移送のどれか。原本も残す操作は自動的な容量削減にならない。
- DB移行が必要になる時期、素材参照先の再指定、開発リポジトリ内への動画保管の必要性。
- ショートと通常動画のどちらを先に完成させるか、字幕・画面比率・素材追加など作品としての最低条件。
- 第15章は資料の説明と根拠IDを持つが、直接URLがなく再確認の追跡性が不足。記載版・SDK・モデル許諾を現在の確認済み事実と扱わない。

## 技術候補の一次資料確認

2026-09-17、公開資料を確認。実行検証と原本の固定コミットとの同一性照合は行っていない。

- [meeting-transcriber 作者README](https://github.com/okamyuji/meeting-transcriber) は faster-whisper を使用し、文字起こし以外に議事録・RAGも扱う。[作者実装](https://raw.githubusercontent.com/okamyuji/meeting-transcriber/main/app/transcriber.py) は時刻付き区間、ログ・端末進捗、テキスト保存等を提供する。GUI・DB・中止制御は別途必要。
- [faster-whisper公式README](https://github.com/SYSTRAN/faster-whisper) に CPU/GPU、start/end/text、単語時刻、VAD の入口がある。必要なASR機能だけを直接利用する案を比較できるが、実素材の品質・長時間性能の保証ではない。
- [CTranslate2公式導入案内](https://opennmt.net/CTranslate2/installation.html) は Windows x86-64 wheel と Windows GPU 対応を記載。ASRの存在だけでWSL必須とはならない。faster-whisperと同案内のcuDNN記載には差があり、採用版の整合確認が必要。
- [MicrosoftのWSLファイル案内](https://learn.microsoft.com/en-us/windows/wsl/filesystems) は相互実行・ファイル共有と実行OSに合わせた配置を説明する。開発でWSLを使うことと、利用時にもWSLを必須にすることを分けて比較する。
- [AviUtl2公式配布ページ](https://spring-fragrance.mints.ne.jp/aviutl/) で本体2.1.9・SDK公開2026/9/5を確認。SDK ZIP本文はWebツールの形式制限で未取得。全操作の遠隔制御・任意の未保存状態復元は今回の一次資料確認でも未確認であり、不可能とも断定しない。

## 質問と判断の順序（初回）

まず以下の独立した前提を確認する。

1. 最も解決したい作業と、現在または想定する制作手順。
2. 対象話者だけを扱う目的と、完成動画に他者の声を残すか。
3. 初回成果の優先軸: 早い制作開始か、統合アプリそのものの完成か。
4. 故意の失敗試験を避ける意図と、隔離したテストデータでの失敗応答の模擬を許容するか。

回答後、目的に合う統合操作の範囲→必要な編集・区間・保存契約→技術比較と実行環境→受け入れ条件の順に進める。前提に依存する質問は回答後に具体化する。
