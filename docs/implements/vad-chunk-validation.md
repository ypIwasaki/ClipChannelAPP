# 5分素材のVAD分割処理検証

A107後の継続検証。補正版の5分動画2本から16kHz単声道PCMを生成し、Silero VAD6.2.2の同一設定で比較した。5分全体を本人のみの正解ラベルとはしていない。A107の確認範囲は各先頭20秒に限る。

## 一括と独立チャンクの比較

threshold=0.5、最短発話250ms、最短無音100ms、余白30ms。方式ごとに新しいプロセスを使った。一括を比較基準とするが、検出の正解とはしない。

| 入力 | 方式 | 検出秒数 | 一括と判定が異なる秒数 | 最大PCM読込み | ピークWorking Set |
| --- | --- | ---: | ---: | ---: | ---: |
| 1本目 | 一括 | 0 | 0 | 300秒 | 259,932,160 bytes |
| 1本目 | 30秒独立 | 68.524 | 68.524 | 30秒 | 244,424,704 bytes |
| 1本目 | 前後1秒重複・30秒担当範囲 | 73.998 | 73.998 | 32秒 | 244,686,848 bytes |
| 2本目 | 一括 | 218.248 | 0 | 300秒 | 260,993,024 bytes |
| 2本目 | 30秒独立 | 190.084 | 30.788 | 30秒 | 244,002,816 bytes |
| 2本目 | 前後1秒重複・30秒担当範囲 | 195.852 | 25.780 | 32秒 | 244,617,216 bytes |

読込みからVADと区間作成まで各3.25〜3.53秒。プロセスのimport時間は含まない。メモリ値はWindows GetProcessMemoryInfoのPeakWorkingSetSizeであり、Pythonやモデル等を含む。各単回測定で、長尺時の上限や性能保証ではない。

重複方式では各チャンクの担当範囲を半開区間にし、その外側の検出を切り落とした。結果の範囲外時刻と重複サンプルがないことをassertで確認。ただし、同じ発言が分割境界で二つの区間になることや、ASR本文の重複を解決した検証ではない。時間グリッドや内部状態が変わる独立処理を、一括と同等とは扱えない。

## 内部状態と512サンプル単位を維持した読込み

ローカル導入したSilero6.2.2のget_speech_timestampsは、先頭で状態をリセットした後、512サンプルずつモデルに入力して確率列から区間を組み立てる。この処理に合わせ、ファイルから512サンプルずつ読み、モデルの状態と入力グリッドを維持した。公式パッケージ内のget_speech_timestamps_from_probsで同じ設定の区間化を実行。

2本とも一括の開始・終了サンプル配列と完全一致した。1本目0区間、2本目102区間。各3.64秒／3.56秒。PCM読込みは512サンプル（32ms）ずつで、全PCMを一括展開しない。一方、確率列9,375個と結果一覧は保持しているため、全処理が時間によらず一定メモリになるとは主張しない。VAD後の区間確定処理のストリーミング化は未実証。

この結果は「状態とグリッドを維持すれば分割読込みで一括結果を再現できる」証拠。1本目を無発話と判断する根拠ではない。一括でも検出できていない点は残り、VAD品質とチャンク整合性を分けて評価する。30秒・1秒重複・閾値0.5を製品仕様として採用しない。

## 判定

S4のVAD部分は5分×2素材で時刻範囲・重複所有・一括との差・読込みメモリを観測。状態維持読込みは一括と一致。10時間等の長尺、ASRの文脈接続・重複除去、話者特徴窓、GUI中止と進捗は未検証。S4全体の合格や仕様確定ではない。故意の失敗注入は行っていない。
