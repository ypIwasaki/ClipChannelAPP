# 非ゼロ開始区間のフレーム選択検証（2026-09-18）

仕様検討中の分離環境での技術検証。原仕様、製品実装、Issue は変更していない。
AviUtl2 2.1.9 + L-SMASH Works r1283、320×180 の標準 AVI 出力を対象とする。

## 問いと切り分け

実動画の4〜8秒を繰り返す8秒出力で、240枚中22枚が期待する60fps元映像の1枚前に一致した。仮説は、(1) 60→30fps変換、(2) 非ゼロの再生開始位置に関係する時刻計算、(3) 似た実画像による照合の曖昧さ。

フレーム番号0〜479を10本の白黒帯として符号化した、8秒・60fpsの人工 H.264/AAC 素材を作成。元映像480枚の番号がすべて正しいことをデコードで確認した。プロジェクトは前半が元素材0〜4秒、後半が4〜8秒。字幕・グループを含めず、映像の番号を直接読む。

| 条件 | 前半の不一致 | 後半の不一致 | 結果 |
|---|---:|---:|---|
| 30fps出力、後半は元素材4秒開始 | 0/120 | 11/120 | すべて期待番号−1、実動画と同じ位置 |
| 60fps出力、後半は元素材4秒開始 | 0/240 | 22/240 | すべて期待番号−1 |
| 60fps出力、後半は別ファイルの0秒開始 | 0/240 | 0/240 | 全480枚一致 |

3番目は FFmpeg で元素材240〜479フレームを切り出し、PTSを0へ移してH.264/AACへ再エンコードした4秒ファイルを使用。番号240〜479自体は保持した。前半は同じ元素材を維持した。

## 判断と限界

画像照合の曖昧さだけでは説明できず、出力fpsを元素材に合わせるだけでも解消しない。yt-dlp取得ファイルを使わずに再現したため、yt-dlp固有の破損を必要条件とはしない。非ゼロ開始を持つ入力経路に関係する再現条件を確認したが、ホストと入力プラグインのどちらの内部処理が原因かは未特定。先行する標準AVI入力クラッシュとは別件として扱う。

区間ごとの0秒開始ファイルは短い人工素材で成立した回避候補。A52の必要時再エンコード許容と矛盾しないが、採用は未決定。実動画の画質、音声同期、任意境界、容量・処理時間、長尺への適用確認が残る。一律の時刻補正は導入しない。

## 2026-09-18：実動画での0秒開始中間ファイル追試

人工素材の回避候補を、利用者提供の2本目（lxYJTSK0y50）の補正MP4に適用した。補正MP4内4〜8秒（60fpsの240〜479フレーム）を切り出し、音声も4〜8秒を切り出して双方のPTSを0へ設定。libx264 CRF18/veryfast/yuv420p、AAC既定設定で再エンコードした。中間ファイルは1280×720・60fps、AviUtl2出力は320×180・60fps・4秒、標準AVI RGB24/PCM16・44.1kHz。

- 中間ファイル生成時間0.522秒、サイズ1,529,552バイト。この端末の単発測定で、長尺性能の予測値にはしない。
- ホストで読込み・保存・書き出しが成立。出力240フレームを元映像の期待位置±2枚で照合し、全240枚が240+n番に最良一致。最小正規化相関0.999408、次点との差の最小値0.00017488。これは画像照合結果でありピクセル完全一致ではない。
- 出力の0.25、1.5、2.75秒から各0.5秒の音声窓を48kHzモノラルへ揃えて照合。元補正MP4との期待原点4秒、中間ファイルとの期待原点0秒の両方で、6窓すべて推定ずれ0サンプル。元との相関0.99697〜0.99953、中間との相関0.99983〜0.99991。可聴品質・口形同期の主観評価や全編同期の保証ではない。
- 中間映像と元の同じ240枚を720pで比較したSSIMはAll 0.988276（Y 0.990337）。再圧縮による差はある。品質の合格しきい値は設定しておらず、指標だけで利用者の品質要件を満たすとは判断しない。

短い実動画でも回避経路の成立を確認した。元データの追加変更はなく、方式の正式採用はしない。任意境界・長尺・可変fps・画質と容量の方針、アプリからの生成／再利用／削除管理は残る。根本原因、書き出し中止・排他E4、失敗復元E5の判定は変更しない。
