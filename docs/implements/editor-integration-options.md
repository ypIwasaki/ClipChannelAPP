## 提案する構成

本体の標準編集機能を基礎に、MP4等の入力・H.264/AACの出力を担うプラグイン、ClipChannelAPPとの連携専用プラグインを組み合わせる案を優先する。特定の効果プラグインの指定はないため、追加の演出用プラグインを先に増やさず、本体の機能と合意済み要求の差を調べる。原本の全操作を扱う希望を数例の操作に縮小する決定ではない。

## 操作対応表

「入口あり」はSDK宣言を読んだ意味であり、外部アプリからの実行・正しい結果・復元を確認した意味ではない。現段階で「対応済み」と判定した行はない。復元が未確認の変更操作を実行しないA38・ADR0003を維持する。

| 操作 | 要求との対応 | 構成案／確認できた入口 | 未決・成立条件 |
| --- | --- | --- | --- |
| 同一元動画のクリップ選択・追加 | ED01〜02、A43 | アプリで元動画の一致を確認し、`create_object_from_media_file`等で配置 | 入力プラグイン、レイヤー・時刻配置規則、失敗時の追加取消し |
| オブジェクト生成・削除 | ED03〜04 | `create_object`、`create_object_from_alias`、`delete_object` | 削除前の関連状態を含む復元、オブジェクトの継続的な識別 |
| クリップの複製・編集・挿入・削除 | A70 | オブジェクト生成・alias・移動・削除等を組み合わせる設計案。完成済みの一括操作ではない | 字幕・効果を含む独立した複製と、後続映像・字幕の移動が要求。複数配置の識別、補助素材の追従、複数オブジェクト変更全体の復元は未確認。素材ファイルの削除とは別 |
| 字幕の新規取込み | A18・22・25 | テキストオブジェクト生成、`set_object_item_value`等で内容を設定する案 | 元時刻→クリップ→編集時刻の対応、表示範囲制限、既存字幕を変更しない取込み単位 |
| 字幕の本文・時刻・位置等の編集 | ED03、A18 | オブジェクト項目の読書き、標準テキスト効果を使う案 | 実際の項目名・文字コード・時刻単位・フォント等の全項目表 |

| プロジェクト保存・再開 | ED06・09、A82 | 本アプリの保存で明示保存。未保存のまま閉じる際は保存／破棄／戻る。SDKには保存／読込通知ハンドラーとプラグイン専用保存領域 | 通知は能動的な保存開始ではない。全体保存・再開の起動経路、未保存検出、結果確認は未確認。A83で未保存時は保存して書き出す／戻るを選び、保存成功後に書出す。保存失敗時は開始しない。A84で書出し中の同一プロジェクトへの変更を止め、完了・中止後に再開すると合意。変更防止・停止完了・排他解除の経路は未確認 |

| 失敗・中止時の自動復元 | ED10〜11、A38 | オブジェクト変更をまとめてUndo登録する説明あり | Undo実行API・未保存状態全体のsnapshot復元は未確認。最後の保存状態へ戻すだけでは不適合 |

上表は合意要件に対する操作分類の対応表であり、本体の全効果・全項目を列挙した最終台帳ではない。対象構成の正式決定には、各操作の名称、項目型・範囲、呼出し先、読戻し、取消し、保存、通常確認の期待結果を持つ台帳へ展開し、未列挙の本体・プラグイン機能との比較が必要。API名の列挙だけでED04を満たしたとは判定しない。

## 次の判断

1. 上記の入出力プラグイン候補版の依存構成・利用条件を確認し、入力形式と出力プリセットを対応させる。x264guiEx 4.11以降のプロジェクト単位の出力設定保存復元は、編集状態全体の復元とは区別する。
2. 保存・出力開始・中止・未保存状態復元の公開された経路を優先調査する。ここが成立しない場合、操作を無効にしたまま完成扱いにせず、代替連携方式や編集基盤の比較へ戻る。
3. 復元可能な操作集合と全操作希望との不足を提示し、要求変更が必要なら理由と代替案を利用者に確認する。自動で手作業へ置換しない。
