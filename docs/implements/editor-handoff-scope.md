# 初版の編集受渡し方針

> 保存範囲の追加合意（2026-09-24）：編集と処理・出力はDB管理せず、編集データの復旧機能は初版から外す。編集ごとのフォルダ分離、明示保存と保存・出力の簡易完了判定は維持する。[ADR-0009](../adr/0009-limit-database-to-speaker-and-analysis.md)を優先する。

2026-09-24の追加合意を含む最新の編集方針。初版では過去の編集をアプリ内で一覧・選択して再開せず、利用者がAviUtl2プロジェクトを直接選んで開く。編集用動画とプロジェクトの対応をアプリのDBや編集台帳に保存する要件は設けない。旧構成案・操作対応表の複数クリップ編集の記述より本書を優先する。元仕様spec-legacy-v0.1.mdは保持し、仕様全体の確定・本体実装・Issue分割は行わない。

## 採用する流れ

1. 本アプリで使用する切り出し区間と順番を指定する。A・B・Cや、同じ区間を再利用するB・A・B・Cなどの列を扱う。
2. AviUtl2に送る前に、本アプリ側の動画処理で指定順の一本の編集用動画を生成する。AviUtl2側で複数の映像クリップの並べ替えは行わない。
3. 各区間の文字起こしから、結合動画の時間軸に合わせた字幕を用意する。同じ区間を複数回使う場合は各配置先の時刻へ対応させる。最終クリップ範囲に重なる対象発言を取り込み、表示時間を範囲内に収め本文を保持する既存方針を引き継ぐ。
4. AviUtl2へ一本の動画と編集可能な字幕のセットを渡す。字幕は動画への焼込みにしない。
5. 字幕調整、画像・BGM・効果音の追加、画面配置、プレビュー、明示保存、完成動画の出力・中止は、今回の変更だけでは削除しない。
6. 編集用動画を生成した後に区間の順番を変える場合、本アプリで順番を組み直して別の編集用動画を生成する。新しい動画に対応するAviUtl2プロジェクト・字幕・補助素材の配置は、既存の編集とは別に管理する。画像・BGM・効果音の配置は各編集用動画に紐づける。
7. 編集用動画はMP4とし、元動画1本の画質を上限にする。完成動画の出力初期値（横1920×1080／ショート1080×1920、H.264/AAC-LC、音声48kHz、1080p SDRの標準fps8Mbps／高fps12Mbps）を基準にするが、元動画と異なる解像度・固定fps・映像ビットレート・音声サンプルレートは元動画を優先する。可変fpsは編集開始時に固定fpsを選ぶ。各切り出し区間のアルファベットと数字の組を使用順に「_」でつないだ名前にする（例：A1_B2_C3.mp4、再利用時はB2_A1_B2_C3.mp4）。編集ごとに別の保存フォルダを使い、編集用動画はデータ用フォルダ内の`media/edits/<編集フォルダ>/`、対応するプロジェクトは`projects/<編集フォルダ>/`に置く。同じ名前で再生成しても旧動画と旧編集を保持する。利用者が動画を選んで編集するため、別の表示用識別子の入力は求めない。

2026-09-24追加合意：編集用MP4の数値的な初期設定が元動画と異なる場合は元動画を優先する。解像度・固定fps・映像ビットレート・音声サンプルレートは選択した元動画の値を初期値とし、元動画が横／ショートの既定解像度と異なっても自動拡大を必須にしない。MP4/H.264/AAC-LCは編集互換形式として維持する。可変fpsには一致させる単一値がないため、従来合意どおり編集開始時に固定fpsを選ぶ。完成動画の出力初期値は別に維持する。

## 既存要件との差分

- AviUtl2連携で複数映像クリップの複製・挿入・削除によって構成を組み替える処理、およびそれに伴う後続映像・字幕の移動は、初版の必須連携から外す。順序と区間の組立てをアプリ側へ移す。
- 本アプリの区間一覧での再生確認・境界修正・分割・結合・追加は維持する。複数の元動画を一つの編集に使う範囲拡張は今回行わず、切り抜き元動画1件の合意を維持する。
- 旧A74〜A78の個々のクリップを親にした補助素材の追従・選択複製・削除は、一本化した初版の編集経路では適用しない。補助素材は編集用動画に紐づけ、動画内の各切り出し区間との親子関係は持たせない。BGM等を区間の継ぎ目を越えて再生でき、映像の終端からはみ出す部分を書き出さない既存方針は維持する。
- 順番を変えて別の編集用動画を生成する場合、既存のAviUtl2プロジェクトと編集済み字幕・補助素材の配置は元の編集に残し、新しい動画に対応する編集は別物として管理する。既存編集を自動移行・時刻変換しない。後から元の編集を開けるよう、既存プロジェクトとその参照先を不用意に上書き・削除しない。
- 参照先の編集用動画・補助素材が移動した場合は利用者がファイルを選んで対応する。初版のアプリ側に参照先の自動再接続・修正機能を設けず、過去の編集を開き直す際に移動先を自動探索することも要件にしない。
- 操作ごとの自動保存は不採用。A82・A83の「保存」、未保存で閉じる際の「保存する／破棄する／戻る」、書出し時の「保存して書き出す／戻る」を維持する。
- 保存から出力までの競合防止と途中失敗からの復旧は、ADR-0006どおり今回見送り。必須検証として再追加しない。

## 検証の扱い

| 内容 | 現在の扱い |
| --- | --- |
| プラグインからの字幕生成入口 | 既存字幕のaliasを取得し、create_object_from_aliasで再生成した実測あり。本文・区間・描画設定は保持され、オブジェクトの所属groupは欠落した。新しい文字起こしからの一括取込み全体を実証したわけではない。 |
| 字幕を複数生成できるかの独立検証 | 実装前の検証から外す。単体生成の入口を再検証するためだけの試験を増やさない。 |
| 本文・件数・字幕時刻・配置 | 字幕取込み機能の実装時テストで確認する。 |
| 指定順の動画結合・字幕時間軸変換 | 実装中に確認する。 |
| 継ぎ目の映像・音声・字幕同期 | 実装後の結合テストで確認する。 |
| 一本の動画と字幕の受渡し全体 | 実装済み・確認済みとは扱わない。ただし字幕複数生成を理由に実装前の必須ゲートを新設しない。 |
| 本アプリからの保存・出力／中止と結果判定 | 下記の簡易判定方式を採用し、制御との接続と判定の動作は実装時に確認する。成立済みとは扱わず、独立した事前必須検証にはしない。 |
| 本アプリからのUndo/Redo・手編集後の履歴整合 | 今回の実装では見送る。AviUtl2自身の標準Undo/Redoを禁止・無効化する意味ではない。 |
| 横／縦・拡大縮小・切り取り・配置 | 本アプリからの反映は実装時に確認する。 |

生成入口の証跡は [編集境界検証](editor-boundary-validation.md)。group欠落は再生成による完全復元の制約として残し、字幕生成自体の不成立とは扱わない。

## 引き続き未合意の事項

- 編集用MP4の初期設定は完成動画と共通になった。元動画の画質上限と異なる解像度・fpsの素材に対する実際の変換方法、編集フォルダの内部名とプロジェクトファイルの具体名は未固定。既存の編集用動画と編集プロジェクトを上書きしない既存合意を守る。元素材と区間・順序情報を残す提案を含め、詳細な保存契約を無断で確定しない。

これらを再検討する際も、回答済みの明示保存・競合防止見送り・自動復旧見送り・字幕複数生成の検証省略は引き継ぐ。

## 保存・出力の簡易完了判定（2026-09-18合意）

利用者の開始時刻・更新日時による確認案に、サイズの安定と内容確認を補った方式を採用する。操作ごとの自動保存を追加する決定ではなく、本アプリの明示保存・書き出し要求に対する結果判定の契約である。

### 編集プロジェクトの保存

1. 作業開始時刻を保持し、保存を指示する前に指定先ファイルの有無・最終更新日時・サイズを記録する。
2. 一つの保存要求につき一度、AviUtl2に保存を指示する。
3. 指定先の新規作成、または保存前の値からの更新を待つ。開始時刻より新しいかだけで判定せず、保存前の値との比較を基本とする。
4. 更新日時とサイズが連続した確認で変化しなくなり、プロジェクトの内容を読み取れたら、初版の簡易基準で保存できたと判定する。単なる存在・更新一回だけでは完了としない。
5. 一定時間確認できなければ「保存を確認できませんでした」と表示する。未確認を保存失敗の確定や成功と混同せず、確認のために保存を自動で繰り返さない。

待機間隔・連続確認回数・確認期限・内容の読取り検査の具体的方法は実装時に決めて確認する。確認期限は結果確認のためのもので、全処理に新しい性能上限を設けるものではない。この方式は厳密な書込み完了保証ではなく、ファイル検査からAviUtl2内部の未保存変更の有無を取得できるとも扱わない。A82・A83の未保存時の分岐は維持し、未保存状態の扱いは実装時の残件として保持する。

### 完成動画の出力

保存と同様に出力先の新規作成・更新、更新日時とサイズの安定、動画の読取りを確認し、さらに予定した長さ・フレーム数等まで出力されていることを確認する。中止・失敗でも更新は止まり、再生可能な部分動画が残り得るため、存在・更新停止・再生可能のいずれかだけで正常完了としない。

予定値との比較方法・許容差・中止要求と観測結果の対応は実装時に確認する。この合意でMP4出力プラグインとの接続や全失敗原因の識別まで実証済みにはしない。必要な確認が揃わない場合は完了と断定しない。保存→出力の競合防止や自動復旧を再び必須条件にしない。

### 実装前検証との境界

動画結合は本アプリ側で行い、字幕の生成入口は既に確認済み。結合・字幕複数生成の実現可能性を調べ直さず、結合結果・字幕時刻・本文・配置と受渡しを実装時・結合テストで確認する。保存・出力の簡易判定と画面設定の反映も実装時に確認し、これらを理由に新しい独立した事前検証を必須化しない。仕様全体の確定や本体実装開始の承認とは区別する。
