# 時刻・変換・出力の契約案

2026-09-18、A96までの合意を前提とする資料調査と設計提案。原本は保持し、実行・素材取得・変換・実装は行っていない。A97で必要時の編集互換ファイル作成とfps選択、A98で最近傍フレーム境界と差の表示・フレーム単位調整に合意した。それ以外の提案は採用済みと扱わない。

## 一次資料で確認した範囲

- FFmpegの入力シークは、再エンコード時のaccurate seekとstream copyで処理が異なる。stream copyだけで指定境界を満たすとは扱えない。[FFmpeg Main options](https://ffmpeg.org/ffmpeg.html#Main-options)
- 固定fps化ではフレームの複製・間引きが生じる。コンテナ側による時刻変更もあり、入力の時刻を保持する指定だけで一致を保証しない。[FFmpeg fps_mode](https://ffmpeg.org/ffmpeg.html#Advanced-Video-options)
- trim/atrimによる切断と時刻の原点変更は別。映像と音声を別々にゼロへ寄せることで元の相対ずれを消さないよう、共通の時間軸を設計する。[trim](https://ffmpeg.org/ffmpeg-filters.html#trim)、[atrim](https://ffmpeg.org/ffmpeg-filters.html#atrim)
- YouTube公式は元と同じfps、MP4、H.264、48kHz音声等を案内する。1080p SDRの推奨映像ビットレートは標準fpsで8Mbps、高fpsで12Mbps。これらは今回の初期値案の根拠であり、投稿成功や画質を保証する条件ではない。[YouTube公式](https://support.google.com/youtube/answer/1722171?hl=ja)

## 取得物・管理素材・編集用変換を分ける

| 条件 | 提案する動作 | 保持するもの |
| --- | --- | --- |
| MP4で取得し、そのまま確認・編集できる | 形式だけを理由に変換しない | 取得物と素材情報 |
| MP4以外だが符号化内容をMP4に収められる | 再圧縮せずコンテナ変更を優先 | 取得物と生成MP4を別ファイルとして保持 |
| 再生・編集互換性のため再圧縮が必要 | 理由と予定設定を表示し、編集用の別ファイルを生成 | 元ファイル・変換結果・対応情報 |
| fpsが一定でない | 編集プロジェクトの固定fpsを選び、その時間軸でプレビューと出力を確認する | 元の各フレーム時刻と変換後の対応。元の長さや再生速度は意図せず変更しない |
| 音声がない／利用可能な音声を読めない | 映像の管理・確認と、音声を必要とする処理の可否を区別 | 元ファイルと原因情報。非発話と推定しない |

編集互換用の第一候補はMP4/H.264/AAC-LC。これは元素材のすべてを1080pに縮小する提案ではない。横・ショートの解像度は完成動画設定とし、素材の解像度変更は別に表示する。HDRや複数音声等の扱いまで、この表で自動変換を承認したとはしない。具体的な入力条件は選定したデコーダー・AviUtl2プラグインで確認する。

固定fps素材は元の有理数fpsを初期値にする案。29.97という表示値から30へ丸めず、30000/1001等を保持する。可変fps・情報不明の素材は推測した値を確定せず、編集開始時に候補と根拠を表示して利用者が選ぶ案。後からfpsを変える場合も、時刻ベースの配置を新しいフレーム境界へ写した影響を示し、黙って長さや配置を変更しない。

## 指定時刻と適用時刻

A52の指定境界優先を、キーフレームへ大きくずらす方式に変更しない。実際の映像はフレーム単位なので、指定値と採用した境界の両方を持つ。

提案する規則:

1. 元動画内の指定開始・終了を保持する。範囲は開始を含み終了を含まない。
2. 切り出しでは元動画の実フレーム境界、編集ではプロジェクトのフレーム境界へ最も近い値を採用する。等距離なら早い方を選ぶ。
3. 指定時刻・適用時刻・差を画面で確認でき、フレーム単位でも調整できる。
4. 丸め後の開始と終了が同じなら、勝手に長くせず修正を求める。動画範囲外の値も黙って別区間へ変えない。余白が動画端を越える場合は既存合意どおり取れる範囲に制限する。
5. 映像・音声・字幕は共通の元動画時刻から変換する。字幕はA69の最終クリップ範囲との交差で選び、A22どおり表示範囲を収めて本文を保持する。フレームへの反映で表示長がゼロになる字幕は本文を失わず、要調整として残す案。

例（設計上の期待値、実測ではない）: 30fpsの時間軸で7.010秒を指定すると適用開始は7.000秒、差は−0.010秒。23.020秒は23.033…秒に対応する。7.000〜23.000秒を指定してその境界が存在すれば、A68どおり7〜23秒を使い余白を再加算しない。

固定fps上の単純な最近傍丸めなら各境界の差は最大半フレームとなるが、これをデコーダー・音声・実出力の誤差保証とはしない。可変fpsの局所間隔は一定ではなく、平均fpsから誤差を保証しない。実出力と適用境界の一致は別途確認する。

## 完成動画の初期設定案

合意済みの横1920×1080・ショート1080×1920、MP4/H.264/AAC-LCを維持する。fpsは上記、音声48kHz、1080p SDRの初期映像ビットレートは標準fps8Mbps／高fps12Mbpsとする（A101で合意）。設定は変更可能。素材の保存用変換へこの出力ビットレートを無条件に流用しない。

Short条件外で「通常の動画として書き出す」を選ぶ場合、画面比率・配置・長さ・出力設定を維持し、横動画化・自動切詰めはしない（A101で合意）。判定は書出し時というA55を維持する。

## 検証で照合するもの

- CFR、VFR、元の音声開始にずれがある素材について、元動画時刻・適用フレーム・音声・字幕の対応を確認する。対象素材は未準備。
- 指定時刻、適用境界、生成ファイルの先頭・末尾、デコード後の長さを記録する。通常確認であり、模擬失敗3件の組合せを増やす提案ではない。
- 再生UIのシーク成功だけで切断精度を合格にしない。デコード・編集・出力の各段階を区別する。
- 元ファイルが残り、変換のみ再実行でき、再実行結果が既存の区間・文字起こしを暗黙に置換しないことを確認する。

A97・98の利用動作は合意済み。A101で上記の音声・1080p SDR画質初期値と通常動画出力時の設定維持も合意済み。未決は、HDR等の入力条件、変換ビルド・設定の固定、時刻対応の実証、編集側のfps変更と復元の成立。FFmpegの部品があることを統合アプリの完成とは扱わない。
