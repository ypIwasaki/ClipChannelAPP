# 保存・復旧・互換性の動作契約案

A101時点の合意を具体化する提案。原本は保持し、実装・試作・Issue分割は行わない。A26の入力保持、A35の削除分離、A41の復旧待ち、A90の閲覧継続、A94の期限削除除外を引き継ぐ。

## 保存失敗からの再試行

[残件台帳](review-exit-criteria.md)の状態表に、利用者へ示す動作を対応付ける。

| 状態 | 表示と操作の案 | 保護する対象 |
| --- | --- | --- |
| 本文・区間の確定保存失敗 | 入力を画面に保持し「保存を再試行」。閉じる場合は未保存であることを表示し、破棄せず戻れる | 確定前の入力、最後に正常保存した版 |
| 変換済みファイルのDB登録失敗 | 「ファイル生成済み・登録未完了」とし、内容を確認して登録だけを再試行 | 生成済みファイルと取得元。ダウンロード・変換を自動的にやり直さない |
| ファイルの置換途中 | 旧ファイル、新ファイル、処理記録を照合し、判別できるまで追加置換を止める | 旧成果物と新成果物。ファイル名や更新日時だけで採用版を決めない |
| 編集適用の結果不明・復元失敗 | 該当プロジェクトへの追加編集を止め、理由・復旧対象・可能な復旧方法を表示 | 適用直前の未保存状態と復元情報。最後の明示保存に勝手に巻き戻さない |
| 外付けドライブ不在 | 不在と必要な再接続を表示。該当データの保存を停止 | 保持中入力と保存済み情報。不在を登録削除に変換しない |

再試行対象の入力版や出力先が変わった場合は、前の上書き確認を新しい対象へ流用しない。再起動後は永続化できた処理記録を照合し、入力保持を保証できないものを復旧済みと表示しない。認証秘密値の永続保存は行わず、必要なら再入力する。

## 復旧情報の表示と破棄

復旧待ちの一覧に、対象プロジェクト／処理、問題が起きた段階、保持している旧・新成果物、復旧に必要なファイルを表示する案。技術的に可能と確認できた復旧操作のみ提示する。復旧ボタンがあるだけで実現経路の未確認を解消しない。

明示破棄では対象と失う復旧手段を示す。素材や完成動画の削除とは別の操作にし、復旧記録の破棄だけで整合性不明のプロジェクトを編集可能に戻さない。復旧成功後も比較対象の状態が一致したことを確認してから編集待ちを解除する。A94は期限で削除しない合意であり、復旧完了時にすべてを黙って自動削除する許可には読み替えない。

## データ形式と依存物の互換性

| 条件 | 提案する扱い |
| --- | --- |
| 読める形式で、ツール・共通モデルだけ不足 | A90どおり取り込み・保存済み情報閲覧は可能。必要な処理のみ停止 |
| 共通モデルが別revision／特徴の前処理が異なる | 既存人物データを消さず、互換未確認として照合を停止。再生成する場合は別版として保持する案 |
| 保存済み編集のプラグインが不足 | 編集情報・素材関係を保持し、不足一覧を表示。同等の見た目を推測で再構築しない |
| 移行形式がアプリより新しい | 元を保持して取込み停止。依存物不足の閲覧許可と、読めない形式の無条件取込みを混同しない |
| 対応する旧形式 | 元パッケージを保持し、別フォルダのコピーを変換・検査してから利用する |
| 未対応の旧形式／破損 | 理由を表示して取り込まない。既存の利用中フォルダに影響させない |

初版で存在しない過去製品形式の変換器を作る必要はない。初版の形式版を定義し、将来変更するときに対応する旧版の範囲を明記する。開発中の全試作DBとの互換を製品要件へ追加しない。具体的な形式版・依存版と検査項目は実装前に固定する技術残件。

## 関連データの削除範囲（A104で合意済み）

A35では関連結果がある元動画情報の削除を止めると合意している。A104により人物登録・文字起こし結果・区間一覧・補助素材情報にも同じ原則を適用する。

- 別の保存済み結果や編集プロジェクトが参照する登録情報は、利用中の参照先を表示して削除を止める。
- 一覧から使わなくしたい場合は「非表示」にでき、既存結果の表示・再開では引き続き参照可能にする。
- 登録情報の削除に伴って関連結果・編集を連鎖削除しない。実ファイル削除とは引き続き別操作。
- 非表示は削除ではなく、復旧用のコピーでもない。再表示でき、引き継ぎにも状態とともに含める。

この範囲拡張と非表示操作はA104で合意済み。人物情報の削除に合わせて過去の結果も消す動作を、実装都合から採用しない。

## 確認方法

本文・区間の保存失敗は既存の模擬失敗第2件、既存成果物保護は第1件、編集復元は第3件へ対応付ける。状態表の全行ごとに新たな故意の失敗試験を追加しない。通常の移行・再接続・削除操作は既存AC08/AC10へ追記する。実証していない異常分岐は結果に明記する。
