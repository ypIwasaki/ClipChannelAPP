## 処理受付・保存とプロセス間通信

画面アプリは処理ID、入力の版、出力予定先、実行状態を管理する。処理プロセスは進捗と新規成果物を返し、保存担当だけが結果を確定する。CPU話者処理環境はtorch/torchaudio 2.8.0を候補とし、ASR環境と分ける。現在のGPUドライバでのCUDA/cuDNN組合せは未確認であり、勝手に更新しない。

通常処理は「待機→実行→成果物検査→保存確定→完了」を基準案とする。中止要求と停止完了を分け、実行中・停止確認中は必要な変更待ちを維持する。応答がない場合の強制停止はA62どおり利用者が選び、アプリが所有する処理だけを対象とする。途中生成物の所有を記録し、入力や既存成果物と区別する。

解析プロセスとは標準入出力の構造化メッセージ、AviUtl2プラグインとは名前付きパイプを候補にする。後者には接続セッション、プロジェクトID、状態の版、操作ID、対応能力を含める。版違い・古い状態への要求は適用前に拒否する。名前付きパイプは既定で必ずローカル限定とは限らないため、ローカル利用者のアクセス制限と遠隔接続の拒否を設計条件にする。[Microsoftの説明](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipes)

適用要求のあとに接続が切れた場合は「失敗して未変更」と決めつけず、結果不明として追加編集を止める。状態を照合せず同じ編集を再送しない。汎用の任意コード実行を連携口にしない。

## AviUtl2連携で満たす契約と残る障害

専用プラグインはオブジェクトとアプリの配置IDの対応、編集指示、変更通知、対応能力の確認を担当する案とする。プラグインを作れば未公開のホスト操作まで使える、とは仮定しない。

| 必要な操作 | 合意した動作／構成上の対応 | 成立確認の状態 |
| --- | --- | --- |
| 複製・挿入・削除 | 字幕・効果は複製後独立、補助素材は選択複製、後続映像と字幕は追従 | SDKに生成・移動・削除等の入口あり。複合操作の全体復元は未確認 |
| 画像・BGM・効果音 | 親クリップへの紐づけ、境界越え可、BGM長は挿入で変えず、親削除時は配置削除 | アプリの関係情報と編集オブジェクトを対応させる案。外部手編集時の整合も必要 |
| 字幕取込み | 最終クリップ範囲に重なる対象発言、表示だけクリップ内へ制限、再取込みは別字幕 | テキストオブジェクト等を使う案。字幕・効果の完全な複製条件は確認が必要 |
| 比率・配置・画質 | 横／ショートの初期設定、途中変更後は利用者が配置調整 | シーン設定入口あり。ただしSDKの一部シーン設定はUndo非対応 |

| 保存・閉じる | 明示保存、未保存時は保存／破棄／戻る | 保存イベントは保存成功の証明ではない。成功判定・未保存状態の取得は未確認 |
| 保存して出力 | 成功した保存内容を出力し、完了・中止まで同じプロジェクトの編集を待つ | 出力中状態は確認。出力開始・中止のアプリ操作、外部側も含む排他は未確認 |
| 失敗復元 | 以前の未保存編集を含む適用直前の状態へ戻す。失敗なら情報保持・追加編集停止 | PROJECT_FILEは全状態snapshotではない。直前状態の取得・復元方法は未確認 |

詳細根拠は[SDK調査](editor-feasibility-research.md)にある。逆操作だけでは、シーン設定や外部プラグイン状態を含む任意の編集を戻せるとは限らない。同じ編集区画内で作ったオブジェクトを直ちに削除する復元もSDKの制約に抵触する。手編集の検出を、すべての変更通知が取得できることと同一視しない。

保存後の出力は、保存対象の版と出力対象の版が一致し、保存成功と編集待ちを確認してから開始する案。保存ボタンの押下やファイル更新時刻だけを成功判定にしない。A38の未対応表示は一時的な保護であり、初版要件の達成とは数えない。困難な機能はA85に従い根拠を添えて個別再検討する。

## 話者処理と文字起こし

1. 利用者が参照音声を選別・試聴し、名前付き人物へ登録する。元の参照音声と生成した特徴の版を両方保持する。
2. 元動画と時刻対応のある音声をチャンク単位で処理する。全長のPCMを一度にメモリへ展開しない。
3. 発話検出と参照特徴との照合で対象発話・非発話・不明を扱う。照合閾値と窓幅は未固定。不確実な区間を対象者と断定しない。
4. 対象発話をASRへ渡し、元動画時刻へ戻す。不明を試聴して対象発話に変更した場合は、その範囲を文字起こしできるようにする案。
5. 本文・時刻の修正、発言の追加、他者発言の除外を保存する。新規実行の結果は既存の修正を上書きしない。

特徴照合は重なり音声の分離ではなく、BGMや他者の声がASRへ混入し得る。ASRが空でも対象者の非発話とは断定しない。A39により全文修正も許容するが、人物指定を処理へ反映せず全員の文字起こしを出す仕様にはしない。追加学習は今回の第一候補には含めず、以前の調査記録を保持する。

## 取得・集計・時刻の提案

yt-dlpは結果項目ごとに動画・音声・情報のみを識別し、成功分を保存して失敗項目を選択再試行する。追加引数は実行前に保護条件との衝突を表示する。保存先、上書き、設定ファイル経由の指定、外部コマンド実行、認証の具体的な入力経路について機能対応表を完成させる必要がある。A95により、認証が必要な取得では利用者が使う認証情報を指定し、秘密値そのものをアプリに永続保存しない。原本の.env管理方針よりこの合意を優先する。外部認証ファイルの参照先を記憶する案は維持し、秘密値をDB・ログ・引き継ぎデータへ保存しない。全オプションを無条件に許す意味ではない。

集計は登録語による一語化、活用の集約、品詞選択、除外語を適用する案。辞書の「正規化形」をそのまま採用すると表記揺れ・意味に近い統合まで入る可能性があるため、A24で認めた活用の範囲を固定例で確認する。出現3回・該当発言2件を区別する。A96により、同じ位置に複数の登録語が当てはまる場合は長い語を優先する。その語が除外語でもあれば集計せず、短い語として数え直さない。除外は集計にだけ適用し、文字起こし本文・字幕は変更しない。

共通時刻は整数マイクロ秒、元動画のPTS/time baseと編集フレーム番号も保持する案。区間は開始を含み終了を含まない。指定境界を優先し必要なら再エンコードするが、フレームに存在しない時刻まで誤差ゼロとは約束しない。可変fpsの扱いと丸め規則、字幕・音声の同期を固定する必要がある。

余白は前後各5秒、動画端で制限し、手修正後は加算しない。A92により、対象話者の発話／非発話／不明が連続する判定区間ごとに初期候補を作る。短い間隔や余白の重複では自動結合しない。A97により一定fpsは元のfpsを初期値とし、可変fpsは編集開始時に固定fpsを選ぶ。A101により音声48kHz、1080p SDRの映像初期値は標準fps8Mbps／高fps12Mbpsとし、画質は変更可能。Short条件外で通常動画として出力するときも比率・配置・長さ・設定を維持し、横動画化・自動切詰めはしない。

## 保存・移行・配布

各データ用フォルダに素材・結果・人物・辞書・配置の安定したIDを持つSQLiteを置く。実ファイル、保存済み編集、復元用情報、Undo履歴を区別する。アプリの区間操作は自動保存、編集プロジェクトは明示保存という合意を維持する。DBのトランザクションで外部編集や動画ファイルまで戻せるとはしない。

ファイルは処理専用の場所へ新規生成し、検査・確定・DB登録までの段階を記録する。再起動時に所属不明なファイルを自動削除しない。引き継ぎは処理と未保存入力の解消後、変更を止めて整合したDB複製と人物データをZIP64へ格納する。A89どおりアプリ・外部ツール・共通モデルは移行先で別途準備する。

A93により、保存済み編集プロジェクトの実ファイルと再開に必要なアプリ側の配置・字幕・効果対応情報を引き継ぎパッケージに含む。参照音声・人物データも実体を含む。素材動画・画像・BGM・効果音・完成動画等の実体は別途移動して再接続する。外部プラグイン固有の依存ファイルは選定構成に応じて確認する。これらの範囲、内容一覧、検査、旧形式対応は[保存・移行案](storage-transfer-validation-proposal.md)を参照。動画の可逆保管は一件ずつ7zへ格納し、容量未削減でもサイズと結果を示して保持する。

アプリの実行環境と利用者データは分けて配置する案。外部ツールは必要版と入手先を案内し、同梱可能性を配布条件ごとに判断する。Qt・音声ライブラリ・モデルを含めた配布物の一覧と許諾は未確定。現在の資料調査から一式を再配布できるとは結論しない。
