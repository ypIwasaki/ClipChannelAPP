# 動画取得・追加引数・認証の動作案

> 最新範囲（2026-09-18）：既存2本の実取得に不要だった認証付き取得、HDR・用途別複数音声などの特殊入力、配布パッケージ・別環境での配布検証は初版から外す。[範囲判定と残す通常経路](initial-scope-pruning.md)を優先する。実行に必要なyt-dlp等、通常の変換・時刻対応、対象話者の照合は維持する。

2026-09-18。A96までの合意を前提にした調査・提案。原本は保持し、仕様確定・実装・導入・取得試験は行っていない。現在の公式masterを読んだ結果であり、原本調査時の2026.08.19との完全な同一性や採用版の動作を保証しない。

## 合意済みの境界

- A6・12: 主要設定のGUI、追加引数欄、yt-dlpの機能案内を提供する。
- A9: 保存・既存成果物・秘密値等の保護条件と衝突する指定は、理由を説明して実行を止める。黙って別の指定へ置換しない。
- A59〜61: 複数動画は個別登録、情報のみは結果表示、音声のみは音声成果物。成功項目を保持し、失敗項目は利用者が選択再試行する。
- A95: 認証は利用者が指定する。秘密値そのものをアプリに永続保存しない。外部認証ファイルの参照先を記憶する案を維持する。
- 原本DL-05〜09: MP4化、変換前の取得済み動画の保持、変換だけの再実行。アプリの自動再投入はしない。

「全CLIの入口を表示する」ことと「任意の外部コードや全引数の組合せを無条件実行する」ことを区別する。A99で任意外部コマンド・追加プラグインを確認済み個別連携へ限定し、A100でブラウザ直接取込みを後続検討とすることに合意。その他の未対応候補まで一括承認とは扱わない。

## 一次資料から分かった点

`--cookies FILE`は読込みだけでなくCookie jarの書出し先にもなる。終了時に`cookiefile`が指定されていれば保存する実装なので、外部ファイルをそのまま渡すだけでは読取り専用にならない。[YoutubeDL.save_cookies / close](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/YoutubeDL.py)

ブラウザCookie取得ではFirefox・Chromium系のDBを一時ディレクトリへコピーする経路がある。「Cookieファイルを出力指定しない」だけで、ディスク上へ秘密情報を一切書かないとは言えない。[cookies.py](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/cookies.py)

設定ファイルは入れ子指定でき、aliasも別aliasへ展開できる。`--ignore-config`だけでは明示的な`--config-locations`まで排除しない。通常出力の文字列解析より構造化出力が推奨される。[公式README](https://github.com/yt-dlp/yt-dlp/blob/master/README.md)

プラグインはPythonモジュールとして実行される。設定値の一覧確認だけで、その副作用を制限できる仕組みではない。[plugins.py](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/plugins.py)

## 機能対応表の基準案

「許可」は対応版で解析・検査できた場合の提案。「停止」はA9の具体化候補であり、未確認の指定を安全とみなさない。GUI上の案内には入力方法、必要ツール、生成物、競合理由を掲載する。

| 分類・代表指定 | 基準案 | 区別・残件 |
| --- | --- | --- |
| 形式・品質・字幕・対象項目の選択 | GUIと追加引数から指定可能 | 指定した成果物の型と実ファイルを照合。音声だけを動画登録しない |
| `-P`、`-o`、付随ファイル・chapter出力先 | 全生成先が処理専用領域内なら対応候補 | 絶対パス、親参照、型別テンプレート、展開後の場所を検査。外側へ書く指定は理由付き停止候補 |
| 上書き・元ファイル削除指定 | 既存成果物への直接上書き、変換前素材の喪失を起こす指定を停止 | 新規領域で生成後、アプリで置換確認する。単に最後へ禁止オプションを足して利用者指定を隠さない |
| 設定ファイル・alias・preset | 展開して実効設定を確認できるものを扱う | 自動読込みは無効化候補。明示ファイルの入れ子まで検査し、秘密値入り設定の全文は記録しない。循環・未解決は停止 |
| `--exec`、`--netrc-cmd`、追加プラグイン | 初版では管理・副作用を確認できる個別連携だけに限定する案 | 任意コードの一般実行は停止候補。A99で合意済み |
| downloader / postprocessor引数、実行物差替え | 採用した実行物と検査できる引数を対応表へ登録する案 | 出力先・外部入力・送信・削除を変え得るため、yt-dlp側だけを検査して通過させない |
| print、JSON、進捗表示の変更 | 利用者向け結果とアプリ内部の成否通知を分ける | 内部通知を壊す指定は停止候補。秘密値を含み得るURLやheaderの無加工保存は行わない |
| `--write-info-json`、metadata埋込み、通信dump | 安全な出力項目を確認できるものを対応 | 全JSONや通信記録をそのまま保存・埋込みする指定は秘密値保護と衝突し得る。`clean-info-json`を秘密値除去の保証にしない |
| retry、再開 | ツール内部の指定とアプリ再投入を区別 | 中止完了を待ち、成功分は維持。失敗した一括処理全体を自動的にやり直さない |
| 更新・cache削除等の保守操作 | 取得とは別の機能として案内する案 | 実行中に採用版を変更しない。利用者の既存共有cacheを取得ジョブの後始末として消さない |

上書きの既定は動画と関連ファイルで同じではなく、`--force-overwrites`は再開条件も変える。downloader・postprocessorの追加引数は別プロセスへ渡されるため、その検査も必要となる。[オプション定義](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/options.py)

表は全オプションの検証済みリストではない。採用版で短縮形・旧alias・設定ファイル経由を含めて実効値を照合する。未掲載引数を「許可済み」と解釈しない一方、未確認のまま全CLI対応完了とも記録しない。

## 認証の具体案

推薦する初版の入口は、利用者が用意した外部Cookieファイル／netrcの指定と、必要時の使い捨て入力である。参照先・認証方式は保存可能、秘密値・入力履歴・認証入りコマンド全文は保存しない。Cookieを読み取って実行時メモリへ渡し、Cookie jarの保存先を設定しない経路を設計候補とする。**通常CLIへ`--cookies`を渡すだけではこの契約を満たさない**ため、独立したPython workerによる入力処理等との比較が必要。全CLI互換をPython APIだけで保証しない。

ブラウザからの直接取込みは便利だが、上記の一時DBコピーを伴う。A95は永続保管をしない合意として記録されており、一時ファイルまで全面禁止とも、無条件許可とも決めつけない。A100により、初版の入口は外部認証ファイルの指定・実行時入力とし、ブラウザ直接取込みは後続検討とする。具体的なファイル形式の対応とCookie書戻しを抑止する方式は技術残件。

認証用URL・proxy認証・header・extractor引数にも秘密値が入り得る。設定の通常保存、失敗入力の再表示、ログ30日保持、移行パッケージのいずれにも秘密値を持ち込まない。再起動後の再試行では、保存しなかった秘密値を利用者へ再入力してもらう案とする。A26の入力保持を秘密値の永続保存の許可へ拡張しない。

ログは処理ID、段階、結果、伏せた原因、成果物IDを中心とする提案。raw標準出力・標準エラーを一度保存して後から置換する方式は採らない。汎用正規表現だけで秘密値の全除去を保証しない。認証入りURLは記録用の安全な識別情報と実行時URLを分ける。外部Cookieファイル等は引き継ぎ・復旧用ファイルの収集対象から外す。

## 成果物・成否・依存

取得、結合・変換、成果物検査、登録を別段階として記録する案。後処理後の実パスと存在を確認し、終了コードだけでMP4完了を判定しない。変換失敗時は取得物を登録可能な取得済み結果として保持し、変換だけ再試行する。複数項目の未着手・失敗・成功・情報のみを区別し、成功済み項目は再試行対象から外す。これらはA59・60とDL-09の具体化であり、新たな自動再試行を追加しない。

YouTubeの完全対応にはEJSと対応JavaScript実行環境の準備が必要。公式EJS案内ではDenoを推奨し最低2.3.0、Nodeは最低22.0.0を示す。公式実行物と必要EJSを用意し、外部componentの実行時自動取得に頼らない構成を候補とする。採用版の固定と実環境確認は未実施。[公式EJS案内](https://github.com/yt-dlp/yt-dlp/wiki/EJS)

## 製品判断の履歴（A99・100で回答済み）

1. **任意の外部コマンド・追加プラグイン等は、初版では保護条件を確認できた個別連携のみ実行可能とするか。** 推奨はこの方式。機能案内へ未対応理由を表示する。A9の一般原則だけから、原本の全CLI操作要求の具体的な縮小まで合意済みとしない。
2. **認証の入口としてブラウザCookie直接取込みを初版に必要とするか。** 推奨はまず外部認証ファイルの読取りと実行時入力にする。直接取込みを含める場合はツールが作る一時DBコピーの扱いも説明し、永続保存なしと一時書込みなしを区別する。

それ以外の実効設定解析、秘密値を保存しないログ生成、Cookie保存抑止、成果物通知、JS実行環境の固定は技術側の残件である。利用者へ実装可否を判断させない。実行確認は許可された実装・検証段階まで行わない。

A99・100反映: 上記2点は推奨案で合意済み。採用版ごとの許可対象一覧と認証入力の実装経路は未確定であり、動作確認済みとはしない。

固定版への補足: 比較対象をyt-dlp 2026.8.19 wheel + EJS0.8.0 + Deno2.9.7へ具体化した。選定版metadataのDeno extraは >=2.6.6を要求するため、上の一般Wiki由来の最低2.3.0をこの構成の条件に使わない。詳細と公表ハッシュは dependency-distribution-register.md を参照。Cookie非保存と全CLI対応はなお未実証。


## 2026-09-18：固定版でのオフライン限定実証

A105以降の検証承認に基づき、既存のWindows分離環境のyt-dlp **2026.08.19**で確認した。実際の認証情報・ブラウザデータは使用せず、`.example.invalid`宛の合成Cookieを利用した。通信・動画取得は実行していない。

1. `cookiefile=None`、`cookiesfrombrowser=None`、`cachedir=False`でYoutubeDLを作成し、`ydl.cookiejar.load(外部ファイル)`で読み込む。Cookieはローカルで生成する要求ヘッダーへ反映された。jarの保存先はNoneのまま、通常close時のsave呼出しは0回、元ファイルの内容・更新時刻は不変。作業領域にも追加Cookieファイルはできなかった。
2. `parse_options`へalias（`--pick`→`-f {0}`）と音声抽出指定を渡し、実効formatがbestaudio、後処理がFFmpegExtractAudio/wavとなることを確認した。後処理本体は実行していない。
3. `--ignore-config --config-locations <明示ファイル>`で、明示ファイル内のformat=worstが反映された。自動設定読込み停止と明示指定の検査は別に必要。

Cookie非書戻しの候補経路と実効設定取得を部分実証したが、認証付き実取得、全CLI互換、別workerの異常終了、OSのページング、ログ・移行パッケージ全体の非保存保証は未検証。`cookiefile=None`を最後に黙って上書きする設計を採用したわけではなく、競合する利用者指定はA9どおり事前に説明して止める。

固定版の`YoutubeDLCookieJar.load`実装には、不正な行を警告としてstderrへ出す経路があり、その行の内容も含まれる。今回は有効な合成入力だけを用いた通常動作確認。生の標準出力・標準エラーを永続ログへ保存してはいけないという設計上の残件は維持する。CLI追加引数・解析エラー・認証入りヘッダーも同様に、未加工の記録を許可しない。

再現資料：`evidence/download-contract/offline-probe.py`、`offline-probe-result.json`。実測値はassertで確認済み。合成Cookieの値・ヘッダー自体を結果JSONへ記録しない。原仕様、本体実装、Issueは変更していない。
