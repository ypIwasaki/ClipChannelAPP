# 話者処理の中止と人物データ引き継ぎの最小検証

A107後の継続指示に基づく、同じWindows PC・固定CPU環境の限定実証。本体実装・正式データ形式の確定ではない。

## 通常の中止要求

専用の子プロセスでlarge-v3 CPU int8を読み込み、本人確認済み20秒音声の遅延評価を開始。開始マーカーから0.5秒後、プロセスが生存中に中止フラグを作成。ASRのgeneratorが次の結果を返した時点でフラグを確認し、結果を完成品として公開せず正常終了した。

- 中止要求からプロセス終了の確認まで18.360秒、exit=0、状態cancelled。
- 元音声、保存済み人物特徴、前回のASR結果のSHA256が開始前と一致。
- 子プロセスの終了を確認して初めて停止完了とした。中止フラグの作成だけでは停止完了にしない。
- 強制終了は実施していない。今回の確認は通常中止1件であり、故意の処理失敗を注入していない。

これは**ネイティブ推論内部の即時中断ではなく、処理結果が返る境界での中止**。18.360秒は単回実測で、上限でも保証でもない。長いチャンク、モデル読込み中、出力書込み中、GUI状態表示、利用者が選ぶ強制停止、長尺メモリ推移は未検証。A42の数値上限なし・状態表示と中止必須、A62の強制停止は利用者が選ぶ、という合意は変更しない。

[検証コード](evidence/a106/cancel_probe.py)・[結果](evidence/a106/cancel-result.json)。制御用ファイルとログは結果に記した新規の検証専用ディレクトリへ残した。本体のジョブ管理を実装した成果物ではない。

## 人物データを別フォルダへコピーして再利用

新規の別フォルダへ参照音声、confirmed-reference.pt、モデルrevision・前処理・人物名等を含むconfirmed-reuse.jsonの3ファイルだけをコピー。移動や元ファイルの置換はしていない。コピー先全ファイルのSHA256一致、コピー元の不変を確認した。

共通モデルをロードする前にJSONの人物名を読めた。続いて別途指定した既存ECAPA共通モデルを用い、コピー先の人物特徴と2本目の音声を照合。cosine=0.7485563755、移行前との差0.0だった。共通モデル重みは引き継ぎフォルダへ入れていない。

これは同一PC・同じ実行環境での別フォルダ再利用。別PC・別依存版、アプリの取り込み・閲覧UI、ZIP64移行、DBとの関連、依存不足時の処理停止は未検証。JSONを先に読めたことだけでA90のアプリ動作全体を合格とはしない。S5は部分確認。

[検証コード](evidence/a106/transfer_probe.py)・[結果](evidence/a106/transfer-result.json)。作成された人物データと音声はローカルに保持し、リポジトリにはコードと結果記録のみ保存。

## 残件への反映

S4は通常中止の境界を一件確認、S5は同一環境の別フォルダ再利用を確認。それぞれ全条件達成ではない。S3の他者・重なり・閾値、S4の長尺・チャンク時刻、S5のアプリ統合、編集E2〜E5は残る。今回、新しい製品判断は追加しない。
