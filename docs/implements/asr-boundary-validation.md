# ASR分割境界の比較

A107で本人のみと確認された2本目07:00〜07:20の同一PCMを使用。Windows CPU、faster-whisper1.2.1、CT2 4.8.2、large-v3固定revision、int8・4スレッド・日本語・beam5・temperature0。前区間本文の引継ぎとVADを無効にし、分割条件以外を揃えた。

比較条件は一括20秒、独立10秒×2、読込み0〜11秒／9〜20秒の重複付き分割。後者の担当範囲は0〜10秒／10〜20秒。語の中点が担当範囲内なら採用候補とする試験的な所有規則を付記したが、生の本文・語時刻は削除せず全保存した。これは製品の重複除去規則の採用ではない。

ASRの語単位は日本語の辞書上の単語とは限らず、頻出語集計の単位にも転用しない。10秒境界や1秒重複を製品仕様へ固定する根拠にはしない。一括出力は比較基準であって正解テキストではない。

初回は検証コードがNumPy由来の真偽値をJSON化できず停止。時刻値をPythonのfloatへ変換して解消し、同じ条件で再実行した。モデルや元音声は変更していない。故意の失敗注入ではない。

コード: [asr_boundary_probe.py](evidence/a106/asr_boundary_probe.py)。結果と境界付近の本文は実測後に以下へ記録する。

## 実測と判断

5回すべて完了。モデル読込みを含む計84.16秒。入力区間内のセグメント時刻（末端0.1秒の検査許容）をassertで確認し、語時刻には読込み開始位置と元動画オフセット420秒を加えた。これだけで発語時刻の正確さを保証するものではない。

10秒境界付近では一括が「出た後だったんですけど」、独立分割後半が「あとだったんですけど」となった。前後1秒重複では前半と後半の両方が「出た」を出力。生結果をそのまま連結すると同じ部分を二重に扱う可能性がある。中点で担当を分けた試験案では前半「出た」＋後半「後だったんですけど」に分けられた。ただし、境界外でも表記・語句が変化しており、一例の接続成功を一般的な重複・脱落解消の証明にはしない。

同じフレーズが続く箇所は一括出力にもあるため、隣接テキストの一致だけを根拠に自動削除する案は採らない。原音で実際に繰り返しているか、モデルが繰り返したかの正解注釈は未作成。

結論: 単純な区間連結は成立未確認。重複読込み＋語時刻に基づく担当割当は比較候補として残すが、正式方式・重複幅・分割長は未決定。生結果と処理条件を保持し、境界の修正が可能という既存要件を維持する。ASR品質のAI採点や自動意味修正は追加しない。
