# 今回の編集連携は保存・履歴・出力の制御を優先する

2026-09-18、利用者は残件1〜3のうち「1. 本アプリからの保存・履歴・出力の制御」を今回の対象とし、「2. 保存から出力までの競合防止」「3. 途中失敗からの復旧」を今回の実装では見送ると決定した。公開制御経路と排他中の復元が未成立であることを踏まえ、これらの保護機能の完成を編集連携の開始条件にする方針から、基本制御を先に成立させる方針へ変更する。ADR-0003とADR-0005中の参照条件のうち、この見送り範囲を今回の必須成立条件とする記述を本決定が上書きする。

操作ごとの自動保存は採用せず、A82・A83の明示保存と「保存して書き出す／戻る」を維持する。ただし保存版と出力内容の一致を競合防止によって保証すること、および失敗時に先行未保存変更まで自動復元することは今回保証しない。途中失敗時には不完全な編集が残り得て、保存版への手動再読込みでは最後の保存以降の変更を失い得る。

実行結果の成功・失敗・中止の判定は1に残し、失敗を成功扱いしない。今回の決定は、編集適用中の手編集待ちや出力中の編集待ちなど他の合意を一括撤回するものではなく、手動復旧の新機能や復旧コピー作成を代替必須要件として追加するものでもない。2・3は後続検討事項として保持し、この決定だけで仕様全体の確定・製品実装開始とはしない。

2026-09-18追加合意：その後の利用者回答により、本アプリからのUndo/Redoおよび手編集後の履歴整合も今回見送る。複雑なクリップ編集をアプリ側の動画一本化へ移したため、履歴連携を今回の必須条件から外す。保存・出力は [編集受渡し方針の簡易判定](../implements/editor-handoff-scope.md)を採用し、更新検出・安定・内容読取り（動画は予定長さ・フレーム数等も確認）を実装時に確認する。従来の「履歴を含む制御全体の事前成立」を今回の必須条件にはしない。明示保存と本ADRの競合防止・復旧見送りは維持する。
