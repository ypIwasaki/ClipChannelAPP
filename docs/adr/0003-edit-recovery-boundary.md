# 編集適用の排他と復元成立を操作実行の条件にする

アプリが編集を適用している間は同じプロジェクトへの手編集を待ち、適用開始前の未保存編集を含む状態を保護する。復元の成立根拠が揃わない操作は未対応と表示して状態変更の実行を止めることで、全操作への入口を無条件に有効化するよりデータ保護を優先する（2026-09-17、仕様再検討A37・A38で合意）。未対応を要件から削除したり全操作対応完了と数えたりはせず、具体的な排他・復元方式は引き続き検討する。

復元処理自体が失敗した場合は、そのプロジェクトへの追加編集を止め、復元用情報を保持して失敗と復旧方法を表示する（仕様再検討A41）。復旧の具体的な操作と編集を再開できる条件は別途定義する。

書き出し中も同じプロジェクトへの編集を待ち、書き出しの完了または中止後に再開する（2026-09-18、A84）。保存した内容と完成動画を一致させるため、出力中の同時編集を許す方式より変更防止を優先する。外部編集側を含む排他と停止完了の検出は未確認であり、中止要求を送信しただけで解除することは意味しない。
