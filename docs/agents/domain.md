# Domain docs

単一コンテキスト構成を使用する。

- 調査前にルートの `CONTEXT.md` と対象領域に関係する
  `docs/adr/` の ADR を読む。
- 未作成ならそのまま進める。
- ドメイン概念を記述するときは用語集の正式名称を使う。
- 未定義の用語は domain-modeling で整理する。
- 既存 ADR と矛盾する提案では、対象 ADR と再検討の理由を明示する。

## 作成・更新

- `CONTEXT.md` は最初の用語が確定した時点で作成する。
  用語集に限定し、実装詳細や仕様は含めない。
- ADR は「変更コストが大きい」「背景なしでは理由が分からない」
  「実際の選択肢とトレードオフがある」をすべて満たす判断に使う。
- ADR は `docs/adr/0001-<slug>.md` 形式で保存する。
- 用語集・ADR の記述形式は domain-modeling スキルに従う。
