# Issue 18: 同じ素材で制作を確認する GUI 操作手順

この手順は、利用者が同じ元動画を使って、ローカル登録から対象話者の確認、文字起こしの手修正、切り出し区間の選択、字幕付き編集、明示保存、完成動画出力までを確認するためのものです。確認結果は末尾の表に記録してください。頻出語から該当発言を開く操作も含めます。

既存の[機械的な工程間検証](../.scratch/clip-production-v1/evidence/18-full-flow.md)では完成動画まで出力できました。ただし、その話者判定と区間選択は検証コードによる暫定操作です。この手順で試聴・映像確認と GUI 操作を行うまで、Issue 18 の最初の完了条件は未確認です。

## 準備

1. Windows から直接使える内蔵・外付けドライブに、今回専用の**空のデータ用フォルダ**を作ります。例: `C:\Users\raimu\AppData\Local\ClipChannelAPP-validation\issue18-gui`。既存の検証データを守るため、[先行検証の Temp フォルダ](../.scratch/clip-production-v1/evidence/18-full-flow.md)は作業先にしません。
2. 元動画、対象話者の参照音声、ローカル ECAPA モデル、ローカル Whisper モデル、AviUtl2 2.1.9 と専用プラグインを用意します。同じ素材を再確認する場合、元動画は `C:\Users\raimu\AppData\Local\ClipChannelAPP-validation\issue06-announcerA\u5Bwx8Vl0U8-55-90-video.mp4`、参照音声は同じフォルダの `u5Bwx8Vl0U8-55-90.wav` です。これらが見つからなければ、本人の声を確認できる別の動画と参照音声を使い、そのパスを記録します。
3. **一つの Python 環境**でアプリを起動します。Windows Python と WSL Python のどちらでも構いません。その環境に Torch・SpeechBrain・faster-whisper・SudachiPy・SudachiDict-core が必要です。モデルと依存物の準備情報は[開発環境の引き継ぎ資料](development-handoff.md)を参照してください。`ffmpeg`・`ffprobe`・`ffplay` を実行でき、完成動画の出力には Windows 版 `ffmpeg.exe` を `CLIPCHANNEL_FFMPEG` へ指定します。AviUtl2 では専用プラグインを読み込んでおきます。Windows PowerShell から起動する場合、次の `$Python` はこのPCに実在する Python 3.12 のパスです。**起動確認用**であり、この環境は現時点で faster-whisper・SudachiPy・SudachiDict-core が不足します。全工程には同じ Windows Python 環境にそれらも準備してください。

   ```powershell
   $Python = 'C:\Users\raimu\AppData\Local\Temp\clipchannel-a105-speaker\venv\Scripts\python.exe'
   if (-not (Test-Path -LiteralPath $Python -PathType Leaf)) { throw "Python が見つかりません: $Python" }
   $FfmpegBin = 'C:\Users\raimu\AppData\Local\ClipChannelAPP-validation\a106\ffmpeg-mirror\ffmpeg-9.0.1-essentials_build\bin'
   $env:PATH = "$FfmpegBin;$env:PATH"
   $env:CLIPCHANNEL_FFMPEG = "$FfmpegBin\ffmpeg.exe"
   Set-Location '\\wsl.localhost\Ubuntu\home\raimu\workspace\ClipChannelAPP\ClipChannelAPP'
   & $Python -m clipchannel.app
   ```

   必要なモデルの既存候補は ECAPA が `C:\Users\raimu\AppData\Local\Temp\clipchannel-a105-speaker\model`、Whisper が `C:\Users\raimu\AppData\Local\ClipChannelAPP-validation\asr-probe\model` です。Temp 内のファイルは残っているか事前に確認してください。

   WSL から起動する場合は、データ用フォルダと動画・モデルを **`/mnt/c/` など Windows から直接使えるドライブ上**に置き、WSL 内のパスで選びます。`/home/...` をデータ用フォルダにしないでください。WSLg、`wslpath`、`powershell.exe` と Windows 側の AviUtl2・専用プラグインを使用します。この環境では WSLg の Tk 起動と WSL→Windows の連携入口を確認済みです。一方、リポジトリの `.venv` は Python 3.14 で、現時点で Torch・SpeechBrain・faster-whisper が入っていません。GUIの起動確認はできますが、全工程には互換性のある WSL Python 環境と依存物の準備が必要です。Windows アプリのデータが通常の `/mnt/c/Users/.../AppData/Local/` に見えないときは、`/mnt/c/Users/raimu/AppData/Local/Packages/OpenAI.Codex_2p2nqsd0c76g0/LocalCache/Local/` 配下も確認します。WSL の `CLIPCHANNEL_FFMPEG` には Windows 版 `ffmpeg.exe` の `/mnt/c/...` パス、または `C:\...` パスを指定できます。

   ```sh
   cd /home/raimu/workspace/ClipChannelAPP/ClipChannelAPP
   export CLIPCHANNEL_FFMPEG='/mnt/c/Users/raimu/AppData/Local/Packages/OpenAI.Codex_2p2nqsd0c76g0/LocalCache/Local/ClipChannelAPP-validation/a106/ffmpeg-mirror/ffmpeg-9.0.1-essentials_build/bin/ffmpeg.exe'
   .venv/bin/python -m clipchannel.app
   ```
4. 元動画の名前、長さ、対象話者、参照音声、使用するモデルの場所を記録します。今回の素材なら元動画は約35.035秒、640×360、30000/1001 fpsです。以降の工程では、登録された**同じ元動画**を選び続けてください。

処理が終わるまでは画面下部の「管理対象の処理」の状態を確認します。所要時間に合格上限はありません。中止を試すことはこの一連の確認に必須ではありません。

## 1. 元動画を登録する

1. 画面上部の「フォルダを選択・切り替え」で準備したデータ用フォルダを選びます。
2. 右側の「ローカル動画を登録」で元動画を選び、媒体確認・編集互換変換の処理完了を待ちます。
3. 右側の登録済み動画一覧に同じ名前が現れ、データ用フォルダの `media/originals/` にコピーがあることを確認します。元の場所の動画を上書きしないことも確認します。媒体変換が行われた場合は、その結果と開始時刻の表示を記録します。

## 2. 対象話者を試聴して文字起こしを修正する

1. 左側の「人物・参照音声」タブを開きます。新しく人物を登録する場合は、名前、参照音声ファイル、ローカル ECAPA モデルフォルダ、照合閾値と分割方式を入力して「人物を登録」を押します。今回の先行検証では閾値 `0.25`、分割方式 `whole-reference` を使いました。この閾値を正解判定として扱わないでください。
2. 人物一覧で対象人物を選び、「参照音声を試聴」で声を確かめます。「対象動画」で手順1の動画を選び、「動画の対象話者に設定」を押します。
3. 「試聴区間を作成」を押し、一覧の各行を選んで「試聴」します。実際に聞こえる声に応じて「対象発話」「対象話者の非発話」「不明」を指定します。照合スコアだけで対象発話へ確定しません。他者だけの発言や重なって判定できない区間を確認した場合は、その判断と時刻を記録します。行の変更後は自動保存の完了表示を待ち、失敗した場合は入力を保持したまま「保存を再試行」を使います。
4. 「ローカル Whisper モデル（対象発話の区間のみ認識）」にモデルフォルダを入力し、「対象発話を文字起こし・別版保存」を押します。対象発話にした区間の本文と元動画時刻が表示されることを確認します。
5. 発言を試聴し、誤字や時刻を直す行を選びます。「開始秒」「終了秒」「本文」を直して「選択行を修正」を押します。認識漏れは「発言を追加」、他者の混入は対象話者の発話から外す操作で確認できます。保存済み情報の該当する `transcripts/*_vN.csv` を選んで「保存版を再表示」を押し、修正結果を確認します。旧版が残っていることも記録します。

## 3. 頻出語から発言を確認する

1. 「頻出語」タブで手順2の**修正済み文字起こし版番号**を入力し、「再集計して別版保存」を押します。
2. 語を一つ選び、表示された発言・時刻を確認します。発言をダブルクリックして元動画がその位置から再生されることを確認します。選んだ語、発言本文、表示時刻、再生で確認した内容を記録します。
3. [M-07の固定例](implements/acceptance-examples.md)は個別機能の期待値です。今回の実素材で語や回数が異なっても、その差だけでは失敗としません。先行検証の修正版では「こと」2回・該当発言2件でしたが、今回の手修正内容に応じて変わります。

## 4. 映像を見て切り出し区間を決める

1. 「切り出し区間」タブで、手順2で使用する文字起こし版番号と前後の余白を入力します。初期値は前後各5秒です。「候補を生成して別版保存」を押します。
2. 候補を選び「映像を再生」で採否を判断します。対象話者が話していない区間や不明区間も、映像を見て判断してください。使う区間は「採用」を選んで「採否を適用」します。
3. 開始・終了を直す場合は、行を一つ選び、秒数を入力して「境界を修正」を押します。必要なら「フレーム境界へ合わせる」「開始±1F」「終了±1F」で適用時刻と差を確認し、最後に「境界を修正」で保存します。分割・結合・手動追加が必要なら同名のボタンを使います。変更後の自動保存完了を待ちます。
4. 保存済み情報の `segments/*_vN.csv` を選び、「選択した保存版を使用」で最終版を開き直します。採用した区間の元動画時刻と使用する順番を記録します。手で修正した境界に余白が再加算されていないことを確認します。

## 5. 字幕付き編集を作って保存・出力する

1. 「切り出し区間」タブで採用区間を選び、「区間を追加」で編集用動画の順番に並べます。「上へ」「下へ」で順番を決めます。固定fpsが必要な入力では値を指定し、「新しい編集を作成」を押します。表示される横／ショートの選択を行い、処理完了後に示される編集用MP4と `.aup2` のパスを記録します。「編集用動画を再生」で範囲と順番を確認します。
2. 「保存・書き出し」タブの「プロジェクトの保存フォルダを開く」から、今回の編集フォルダの `.aup2` をAviUtl2で開きます。元動画の別編集や古い `.aup2` を開かないよう、表示パスを確認します。
3. 保存済み情報から、**同じ元動画の修正済み文字起こしCSV**を選び、「切り出し区間」タブの「字幕をAviUtl2へ追加」を押します。直接追加できない場合は、表示された `.ccsub` をAviUtl2の「ClipChannel → 字幕を追加」から選びます。字幕が編集可能なオブジェクトとして入り、本文・件数・表示位置・時刻が編集用動画に合うことを確認します。
4. 「画面・字幕」タブで画面と字幕の配置を設定し、「画面設定をAviUtl2へ渡す」「AviUtl2結果のプレビューを開く」で字幕が画面内に見えることを確認します。今回の640×360素材では先行検証で字幕Y=`0`、サイズ=`24`を使いました。実際の表示を見て調整してください。字幕を一つ編集する場合は「選択字幕を別版保存」を使い、元の文字起こしが変わらないことを確認します。
5. 「保存・書き出し」タブで今回の `.aup2` が選ばれていることを確かめ、「保存」を押します。保存完了の表示を確認してから「完成動画を書き出す」を押し、`exports/` 内に**新しい**MP4名を指定します。未保存の確認画面が出たら、内容を保存して書き出す操作を選びます。保存失敗や完了未確認の表示が出た場合、完成扱いにせず理由を記録します。
6. 完成動画を再生し、選んだ範囲・順番・字幕の表示と音声を確認します。保存先、動画の長さ、画面サイズ、映像・音声の有無を記録します。先行検証の277フレーム・約9.243秒は**先行検証で選んだ区間にだけ対応**する値です。今回の採用区間が違えば同じ値を要求しません。
