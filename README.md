# ClipChannelAPP

アーカイブ動画の取得、対象話者の文字起こし、切り出し、編集、管理を一つのアプリから扱うプロジェクトです。

現在は機能を段階的に実装中です。保存済みデータの閲覧、ローカル動画登録、認証不要URLの取得を扱う簡易画面があります。

```sh
python -m pip install -r requirements.txt
python -m clipchannel.app
```

媒体の確認と編集互換変換には、別途 `ffprobe` と `ffmpeg` を実行パス上に用意してください。取得した元ファイルは `media/downloaded/` に保持し、登録した動画は `media/originals/` に置きます。変換が必要な場合のMP4は `media/prepared/<元ファイル名>/editing-<識別子>.mp4` に保存し、同名のJSONに映像・音声の開始時刻と元動画との対応を記録します。変換に失敗した場合も元動画を保持し、動画を選択して「媒体確認・変換（再試行）」を実行できます。音声のみの結果は `media/audio/` に保存します。

編集用字幕を追加するには、区間タブで編集用MP4を作成し、同じ元動画の保存済み文字起こしCSVを一覧で選んで「字幕をAviUtl2へ追加」を押します。`projects/<編集フォルダ>/` に取込みファイルを別版保存します。AviUtl2に対応する編集用動画を配置し、本アプリの「保存・書き出し」からプロジェクトを保存して、[字幕取込みプラグイン](editor-plugin/)の「ClipChannel → 字幕を追加」でファイルを選びます。再取込みは既存字幕を変更せず、別オブジェクトを追加します。元の文字起こしCSVも変更しません。

プラグインのビルドにはAviUtl2 SDKとWindows C++ビルド環境が必要です。Visual Studio の x64 Developer Command Prompt で、`AVIUTL2_SDK` に `plugin2.h` のあるフォルダ、`WIN_SDK_PACKAGES` に Windows SDK NuGet パッケージの親フォルダ、`WIN_SDK_VERSION` に SDK の版を設定して `editor-plugin/build.cmd` を実行します。生成した `clipchannel_subtitles.aux2` をAviUtl2のプラグインフォルダへ配置します。AviUtl2 2.1.9で字幕の追加・保存・再取込みを検証済みです。

「補助素材」タブでは、現在作成した編集用動画に画像（PNG/JPEG/BMP）・BGM・効果音を追加できます。外部ファイルは `media/supporting/<編集フォルダ>/<素材識別子>/` へコピーし、原本を変更しません。開始フレーム・長さ・画像位置と拡大率・音声の素材開始秒と音量を指定して「配置をAviUtl2へ適用・プレビュー」を押します。上記の専用プラグインを更新し、AviUtl2で対応する編集用動画を先頭に配置してください。プロジェクトは本アプリの「保存・書き出し」から `projects/<編集フォルダ>/` に保存できます。調整時は同じ素材の配置を更新し、重複追加しません。画像と、プレビュー位置から最大5秒のAviUtl2のミックス音声を確認できます。

BGMは全長で追加し、編集用動画の継ぎ目や終端では切り詰めません。音声の長さはフレーム単位で表現します。適用時に映像終端までをAviUtl2の選択範囲に設定し、プレビュー音声もその終端で止めます。完成動画の保存・書き出しは「保存・書き出し」タブから操作します。配置の指示ファイル `.ccmedia` は版を分けて保存しますが、AviUtl2プロジェクト自体の保存は明示的に行ってください。新しい編集用動画には既存の補助素材配置を移しません。

補助素材の自動テストは `python -m unittest tests.test_supporting_media -v` で実行できます。Windows の隔離したAviUtl2にビルド済みプラグインとMP4入力環境を用意し、`CLIPCHANNEL_TEST_AVIUTL` をその `aviutl2.exe` に設定すると、`python -m unittest tests.test_supporting_media_editor -v` で実機の描画とミックス音声を検証できます。検証専用プロセスはテスト終了時に停止します。

作業規則は [AGENTS.md](AGENTS.md) を参照してください。スキルは `.agents/skills/`、導入元の記録は `skills-lock.json` にあります。

「保存・書き出し」タブの「保存」は、未適用の画面・字幕・補助素材の入力をAviUtl2へ適用し、開いている対応プロジェクトを明示保存します。保存前後の更新日時・サイズ、3回連続（250ms間隔）の安定とプロジェクト内容の読取りを確認します。10秒以内に確認が揃わない場合は「保存を確認できませんでした」と表示し、入力を保持します。確認のための自動再保存は行いません。初回は編集用動画を置いたAviUtl2の無題プロジェクトを開き、本アプリで `projects/<編集フォルダ>/` 内の新しい保存名を選びます。既存ファイルへの初回保存は拒否します。保存済みプロジェクトが1件なら自動選択し、複数件なら保存対象を選びます。

「完成動画を書き出す」では、未保存なら「保存して書き出す／戻る」を選びます。保存を確認できるまで出力しません。アプリを閉じるときは「保存する／破棄する／戻る」を選べます。保存は手編集を含むAviUtl2の現在の内容を対象とし、ファイル確認は簡易判定です。保存から出力までの原子的な競合防止と失敗時の自動復旧は行いません。

出力初期値は横1920×1080／ショート1080×1920、編集と同じ固定fps、標準fps（30以下）8Mbps／高fps12Mbps、音声48kHzです。解像度・fps・ビットレート・音声サンプルレートを変更できます。形式はMP4/H.264/AAC-LC、SDRです。ショートは正方形または縦長・3分以内を判定します（[YouTube公式ヘルプ](https://support.google.com/youtube/answer/15424877)、2026-09-25確認）。条件外なら「編集・設定を直す／通常の動画として書き出す」を選び、通常動画を選んでも現在の設定を維持します。投稿後の分類を保証する機能ではありません。

プラグインはAviUtl2の描画・ミックス音声をWindows版FFmpegへ渡します。Windows側で `ffmpeg.exe` をPATHに置くか、アプリ起動前に環境変数 `CLIPCHANNEL_FFMPEG` に実行ファイルの絶対パスを設定してください。WSLから起動する場合もエンコーダーにはWindows版を使い、アプリ側の検査にはWSLの `ffprobe` を使います。出力中は同じ編集のアプリ入力とAviUtl2のウィンドウを無効にし、「書き出しを中止」の要求だけでは解除せず、実際の停止後に再開します。BGMが映像より長くても最後の映像までを出力し、フレーム数・長さ・解像度・fps・音声・形式の確認が揃った場合だけ完成を表示します。既存の完成動画は上書きせず、中止・失敗で残ったファイルは完成扱いしません。

取得・情報取得、ローカル動画登録と媒体変換、対象話者の照合・文字起こし・修正保存、フレーム境界の確認・調整、編集用動画の作成は、画面下部の「管理対象の処理」で状態と経過秒を確認できます。「通常中止」は停止を要求し、処理とその子プロセスの終了を確認するまで編集とフォルダ切替を待ちます。停止待ちでも未保存の入力は保持します。終了時の処理時間は固定して表示します。

通常中止の要求から3秒経っても終了しないときだけ「強制停止…」を選べます。3秒は選択肢を有効にする待機時間であり、処理の時間制限や自動強制終了の期限ではありません。確認画面で対象と影響を確認してから、利用者が明示的に実行します。アプリの管理プロセスとその子プロセスだけを止め、同名の別プロセスは対象にしません。完成した取得項目と既存の成果物は保持し、途中の作業ファイルを完成扱いしません。強制停止後に作業ファイルが残る場合があります。

AviUtl2の書き出しには「書き出しを中止」と「強制停止…」を用意しています。描画・エンコードが応答しない場合の強制停止は、その書き出しを受け付けたAviUtl2とエンコーダーを終了するため、AviUtl2内の未保存編集を失います。確認画面にこの影響を表示し、アプリ側の入力は保持します。出力後の動画検査中は検査プロセスだけを停止し、AviUtl2の未保存編集には影響しません。いずれも実際の停止を確認してから操作を再開します。強制停止による編集の自動復旧は行いません。

「管理・保管」タブでは人物・登録語・除外語・保存済み結果・動画を非表示／再表示できます。非表示は辞書の働きや保存済み結果を変更しません。「登録情報を削除…」では実ファイルを残し、「実ファイルを選んで削除…」で対象パスを確認してから別に削除します。データ用フォルダの外の元ファイルは対象にしません。保存済み結果が参照する人物・辞書・元結果・元動画や、選択中の対象話者は削除を止めます。人物の参照音声・特徴ファイルは人物登録を削除してから別に削除できます。

新しい解析結果には、保存時点の参照を同じ場所の `<結果名>.refs.csv` に保存します。旧CSVの参照を確定できない場合は削除を止め、非表示を案内します。登録削除後も結果ファイルが残っている間はその参照を保持します。一覧の表示設定は `catalog/list-state.csv` に保存します。結果と参照の書込みが中断した版は再利用せず、次の版で保存します。

「動画を保管…」はZIP64形式で `archives/` へ保存し、「保管物を展開…」は `media/restored/<別フォルダ>/` へ毎回新しく展開します。元動画・保管物・過去の展開物は保持します。動画のSHA256を保管物に記録し、圧縮後と展開時に検証します。圧縮前後のバイト数と削減量を表示し、減らない場合も「容量は削減できなかった」と表示して保管物を残します。展開物を制作に使う場合は「ローカル動画を登録」から選べます。保管・展開は画面下部の管理対象処理で通常中止・明示的な強制停止を操作できます。

管理対象処理の終了時には、処理名・状態・経過秒・UTC時刻だけを `logs/` に保存します。データ用フォルダを開いたとき、処理終了時、管理タブの整理ボタンで、30日以上経過した通常の `.log` を整理します。現時点では復旧情報とログの対応台帳がないため、`recovery/` に項目があれば全ログを保持します。編集の自動復旧機能を追加するものではありません。
