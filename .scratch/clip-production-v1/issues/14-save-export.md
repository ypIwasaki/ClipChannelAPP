# 14: 編集を明示保存し、完成動画を書き出す

**GitHub Issue:** https://github.com/ypIwasaki/ClipChannelAPP/issues/14

**参照元:** `docs/implements/spec-for-issues.md`（統合仕様書）

**What to build:** 利用者が編集を保存し、内容を反映した完成動画を出力できる。

**Blocked by:** 11: 編集可能な字幕をAviUtl2へ渡す; 12: アプリからAviUtl2の画面と字幕を編集する; 13: 補助素材を追加して配置する

**Status:** ready-for-agent

## 完了条件

- [x] 未保存で閉じる・書き出す際に仕様の選択肢を示し、保存失敗時は内容を保持して書き出しを始めない。
- [x] 保存は前後状態・更新の安定・内容読取りで、出力は予定長・フレーム数等も加えて簡易判定し、不確実なら成功と断定しない。
- [x] 横・ショート、音声48kHz、SDR、fps別ビットレートの初期値と変更可能な設定を反映する。補助音声がはみ出しても最後の映像の終了までを出力する。
- [x] ショート条件外では書き出し時に二択を示し、通常動画を選んでも現在の比率・配置・長さ・設定を変えない。
- [x] 出力中は同じプロジェクトへの編集を待ち、完了または中止後に再開する。

## 実装・検証

2026-09-25: 依存先 Issue 11・12・13 の完了条件チェック、実装コミット、検証記録を確認して着手した。着手時のコミットは `fc959cb38931ef7c700dd83bff06026a4e8605d6`。Status はリポジトリ規約の分類値を維持する。

- 「保存・書き出し」タブを追加した。未保存で閉じる際は「保存する／破棄する／戻る」、未保存で出力する際は「保存して書き出す／戻る」を表示する。未適用の画面・字幕・補助素材を適用してから明示保存し、確認できない場合は入力を保持して出力へ進めない。保存再試行時に同じ字幕を重複追加しない。
- 保存は要求前のファイル状態と比較し、250ms間隔で3回安定した更新日時・サイズ、プロジェクト形式・編集オブジェクト・対応動画の内容読取りで簡易確認する。10秒以内に確認できない場合は未確認とし、自動再保存しない。未保存判定は現在のシーン・オブジェクト内容と編集通知を保存時の指紋と比較し、再読込み後など不明確な場合は保守的に保存を要求する。
- AviUtl2の描画・ミックス音声をWindows版FFmpegへ送り、字幕・補助素材を含む完成動画を出力する。横1920×1080／ショート1080×1920、音声48kHz、SDR、標準fps8Mbps／高fps12Mbpsを初期値とし、解像度・fps・ビットレート・音声Hzを変更できる。ショートは正方形・縦長かつ出力フレーム換算で3分以内と判定し、条件外の通常出力でも設定を維持する。
- 出力中はアプリの編集入力と対象AviUtl2のウィンドウを無効にし、ブリッジからの編集も拒否する。中止要求だけで解除せず、描画とエンコーダーの停止後に再開する。ホスト終了を検出した場合も成功としない。出力は更新・安定・全フレーム読取り、予定フレーム数・映像／音声の長さ、解像度・fps・H.264・BT.709・AAC-LC・サンプルレートを検査する。fps変換時は最後の映像を欠かさないようフレーム数を切り上げ、映像の丸めは出力1フレーム未満、音声は元の映像終端で止める。

### 検証結果

- WSL: `python -m unittest discover -s tests -v` は41件中40件成功、Windows専用実機テスト1件をスキップした。同じ既存実機テストをWindows/AviUtl2 2.1.9で別途実行して成功した。
- `save_export.py`、`save_export_ui.py`、`editor_bridge.py`、`supporting_media_ui.py` のPyrightはエラー0件。`app.py` は既存の診断が44件から42件となり、新規診断はない。リポジトリ全体の型検査成功とは扱わない。
- MSVCでプラグインをビルドした。隔離したAviUtl2で公開APIによる保存、保存後の未保存状態解除、字幕描画を確認した。4秒・10fpsの映像と6秒BGMから24fps・96フレームの出力を確認した。出力中の編集拒否、中止の実完了後の再開も確認した。
- fps端数例: 元の31フレーム／10fps（3.1秒）を320×180・24fpsへ出力し、公開APIの完了判定に成功した。独立したffprobeの読取りも75フレーム、映像3.125秒、音声3.100秒、H.264/yuv420p/BT.709、AAC-LC/48kHzと一致した。
- 新規のTDDテスト追加についてはテスト境界の確認に回答がなかったため追加していない。既存の回帰テスト、実機での操作確認、独立した出力ファイル検査で検証した。
- 初回保存: 一時コピーのプラグインでSDKを使って無題の検証用プロジェクトに動画を置き、その後は製品と同じ保存コードを通した。160×90・10fps・40フレームの動画を含む未保存状態から、公開APIで新しい `.aup2` の保存確認に成功し、保存後の未保存状態解除と対応動画の内容読取りを確認した。準備用コードは製品ソースへ追加せず、確認後に製品版プラグインを再ビルドした。Windows 11の保存ダイアログのファイル名欄にも対応した。
