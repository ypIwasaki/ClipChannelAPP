# 作業別UIの本番実装と検証

2026-09-28。仕様と承認済みの更新C案を本番Tkinter UIへ反映した。
Windows実機の完成条件は未検証のため、保証対象3表示倍率での完成判定は保留する。

## 合意した seam と実装

利用者が調査後の4つの seam を「構いません」と確認した後に実装した。

| seam | 公開 interface と対象 |
|---|---|
| アプリ画面 | `build_app(data=..., preferences=..., display=...)` が返すTk画面の作業・タブ・表示・項目選択。実データ用フォルダ、設定保存先、画面領域をテストから指定できる。 |
| ウィンドウ設定 | `WindowPreferences.load(DisplayArea)` / `save(UiState)`。初回設定、永続化、画面領域に合わせたサイズ・位置補正。 |
| 常時表示の処理操作 | 既存の `ProcessPanel.start()` と `SaveExportPanel.export()` を実行し、画面の中止・強制停止から操作する。 |
| 独自ダイアログ | `choose_action()` の選択結果と、画面から開くプレビュー・案内・警告・エラー・確認。 |

`responsive_ui.py` は固定ページ、作業ナビゲーション、内部スクロール、幅に応じた操作の折り返しを持つ module。
`window_preferences.py` は設定の読み書きとウィンドウ配置を持つ module。
`dialogs.py` は本文と操作を分けたダイアログおよび画像全体の表示を持つ module。
`ui_theme.py` は役割別配色をまとめる。
試作HTML・試作サーバーは本番から読み込まず、参照資料として残す。

全8タブと取得・媒体操作を一度だけ生成する。作業切替では関連タブを表示し、入力変数・選択・処理を作り直さない。
メインUIにCanvasスクロールや可動の分割境界は置かない。
表示と項目の選択を固定領域に置き、一覧・本文・展開した詳細設定の内部だけをスクロールする。
処理中の入力ロックはナビゲーションと表示切替を除外する。
処理状態の長文は固定高さの本文領域に収め、中止・強制停止を独立して表示する。
中止要求だけでは編集ロックを解除せず、既存の処理所有者による停止確認を維持する。

ウィンドウ設定の既定保存先はWindowsでは `%LOCALAPPDATA%/ClipChannelAPP/ui.json`、その他では `~/.config/ClipChannelAPP/ui.json`。
動画・CSV・プロジェクトの保存規則とは分け、正常に終了する段階で保存する。
初回は中サイズ・動画を準備、以降は前回の通常サイズ・最大化状態・作業・タブを復元する。
Windowsの利用可能領域はモニターの作業領域から取得し、DPIに応じたウィンドウ枠・タイトルバーの寸法を差し引く。
参照：[GetSystemMetrics](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getsystemmetrics)、[GetSystemMetricsForDpi](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getsystemmetricsfordpi)、[GetDpiForWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow)。このWindows経路の実行確認は未実施。

## テストと検証環境

WSLのTk表示環境、プロジェクトの `.venv/bin/python` を使用。
新規テストは `tests/test_responsive_ui.py` と `tests/test_responsive_dialogs.py`。
機能ごとに公開 interface で失敗するテストを実行してから実装した。
作業切替、初回設定と画面補正、表示切替、全機能への到達、共通中止、設定エラー時の展開、長文ダイアログ、画像全体表示、選択保持、内部スクロール、長いフォルダ名、完了案内について、この順で必要な実装を増やした。
既に成立した復元や書き出し中止の経路には追加の統合テストを実施した。

表示条件は利用可能領域1920×1040を仮定し、Tkの文字倍率を100%・125%・150%相当に変更した。
各倍率で70%・85%・100%の寸法を使う9条件を確認した。
100%寸法は大サイズ相当の通常ウィンドウであり、Windowsの最大化そのものの検証ではない。
操作の座標だけでなく、ボタンが必要とする幅を確保し、ラベルが切れないことも検査した。
150%・小相当では、全9機能の結果・詳細設定・自動表示を巡回し、内部スクロールを含めて入力・操作へ到達できることを確認した。

メディア・設定・画像は `TemporaryDirectory` に作成した。
中止・強制停止は、このテスト専用に起動した処理を使った。
書き出しUIのテストでは一時動画・一時プロジェクト・一時保存先を使い、AviUtl2状態取得と書き出しの外部接続部分、ファイル選択だけを置き換えた。
既存の実動画・実CSV・実プロジェクトを使った取得、解析、保存、削除、書き出しは実行していない。

配置に依存していた既存テスト1件は、ボタンの親Frameからではなく機能タブから対象を選ぶよう変更した。
ダイアログを置き換えたため、既存のモック先も共通ダイアログの interface に変更した。保存規則に関する期待値は変更していない。

検証コマンド（リポジトリのルートで実行）：

```sh
.venv/bin/python -m unittest discover -s tests -q
git diff --check
.venv/bin/python -m compileall -q clipchannel
```

初回実装時の結果：97テストを実行し、96件成功・1件スキップ。スキップは専用Windows AviUtl2を必要とする既存の補助素材統合テスト。
`git diff --check` と `compileall` も成功した。検証中の実データ変更は行っていない。

## 利用者確認後の修正と操作マニュアル

2026-09-28、利用者からアプリの動作を確認できた旨と、マニュアル作成後のプッシュ依頼を受けた。
表示倍率ごとの確認内容までは報告されていないため、上記の実機未検証項目を検証済みに変更しない。

- 再起動直後に編集用動画が未選択だと保存フォルダボタンが何もせず終了する問題を再現し、`projects` を開くよう修正。現在の編集があれば従来の編集サブフォルダを開く。データ用フォルダ未選択は案内する。
- マニュアル撮影時、短い確認文と複数の選択ボタンがあるダイアログで本文の高さが8pxになる問題と、ボタン下端がダイアログ外へ6pxはみ出す問題を発見。公開ダイアログinterfaceで失敗するテストを先に追加し、操作行が後から折り返しても本文の領域を確保するよう修正。操作行の寸法計算にはFrameの内側余白も含めた。
- `docs/manual/manual.md` とオフラインHTML、赤枠付きの58画像を追加。全9タブ・41表示項目、実際の一時処理の実行中／停止待ち／停止完了、共通確認ダイアログ、説明用プレビューを収録。
- 画像・編集用動画・プロジェクト・CSV・保管物は一時データのみ使用。AviUtl2の本体、Windows標準ダイアログ、ネット取得・解析モデル・実AviUtl2連携の画面は未収録または未実行としてマニュアルに明記。
