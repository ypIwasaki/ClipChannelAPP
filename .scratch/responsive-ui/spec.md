# 作業別UIとウィンドウサイズ対応

## 状態
2026-09-28、利用者の最終確認により変更範囲と完成条件を確定。A1〜A16および配色の追加合意を反映済み。同日、メインUI全体のスクロールを廃止したC案の更新試作を利用者が承認し、配置・配色・表示切替の確定案とした。その後、利用者がテスト対象のseamを確認し、本番Tkinter UIへの実装と自動検証を実施。Windows実機の3表示倍率・最大化等は未検証であり、保証対象での完成判定は保留する。詳細は [本番実装と検証](implementation.md) を参照。

## 目的
1920×1080の画面で、UIが隠れることを理由に利用者がウィンドウサイズを調整しなくても、必要な操作に到達できるようにする。作業と関係のないUIは表示切替で非表示にする。メインUI全体はウィンドウ内に収め、全体スクロールを行わない。リストや「▷」などで表示を切り替える要素の内部スクロールは許容する。

## 調査結果
- Tkinterの起動サイズは1180×720、最小サイズは960×600（clipchannel/app.py）。
- 横分割の左側に8タブ、右側に取得・媒体操作を常時表示する。
- 管理・保管以外はタブ本文全体のスクロールがなく、固定幅入力・横並び操作・縦積みフォームがある。
- プレビュー、補助素材プレビュー、保存・書き出しの独自ダイアログも対象。
- CONTEXT.mdとADR-0001〜0009を確認。アプリのウィンドウ配置に関する既存ADRはない。編集用動画の画面設定は本仕様のウィンドウサイズとは区別する。

## 合意した変更範囲
既存の全8タブ、取得・媒体操作、共通ヘッダー、処理状態、アプリ独自の確認・設定・プレビューダイアログを対象とする。Windows標準のファイル選択画面と外部AviUtl2の画面は対象外。
作業分類、配置、ナビゲーション、スクロール、文字の折り返しに加え、ボタン・テキスト・表示領域の視認性を改善する配色と装飾を変更する。従来の「現在の配色・装飾を引き継ぐ」という合意は、A15・A16の追加合意により変更する。

### 作業分類
| 作業 | 機能 |
|---|---|
| 動画を準備 | 取得・媒体操作 |
| 解析・切り出し | 人物・参照音声、頻出語、切り出し区間 |
| 編集・書き出し | 画面・字幕、補助素材、保存・書き出し |
| 保存結果を確認 | 保存済み情報 |
| データを管理 | 管理・保管 |

作業は利用者が手動で切り替える。処理完了時に自動で画面を切り替えず、次の作業への案内を出す。作業切替で入力内容、選択、実行中の処理を保持する。作業選択、処理状態、中止操作はどの作業でも確認できる。

### ウィンドウサイズ
- 利用可能な画面領域を基準に、小は幅・高さの約70%、中は約85%、大は最大化。
- 小を最小サイズとし、中間サイズでも幅に応じて配置を自動調整する。
- 初回は中、次回以降は前回のウィンドウサイズを復元する。
- 画面条件の変更で収まらない場合は利用可能な領域に補正する。
- 小・中・大をいつでも選び直せる。
- 1920×1080、Windows表示倍率100%・125%・150%を保証対象とする。1366×768は保証対象外。

## 完成条件
1. 対象3表示倍率で、小・中・大のすべてから全作業・全タブへ移動できる。
2. メインUI全体はスクロールせずに収める。全入力・操作へ明示的な表示切替、リストや展開要素の内部スクロールで到達でき、ウィンドウ拡大や分割境界の調整を必要としない。
3. 選んだ作業に関係のない画面を非表示にし、必要な機能へ明確な切替操作で戻れる。
4. 作業選択・処理状態・中止操作をどの作業でも確認でき、長い状態文でも操作が隠れない。
5. 作業・タブ・サイズ切替で入力、選択、実行中処理を失わない。
6. 初回の中サイズ、前回サイズの復元、画面条件変更時の補正が成立する。
7. 独自ダイアログは利用可能な画面領域に収まり、確認・取消等の必要な操作へ到達できる。プレビューは画像全体を確認できる。
8. 空画面に加えて、データ表示中、長いパス・本文・状態文、処理中と失敗表示で上記を確認する。
9. 既存の取得、人物・参照音声、文字起こし、頻出語、切り出し区間、編集用動画・編集用字幕、補助素材、保存・書き出し、管理・保管の処理と保存規則を維持する。

## 追加合意
- 比較試作のC案（工程リスト＋プレビュー重視）を採用する。メインUI全体のスクロールは使わず、必要に応じて操作・結果・詳細設定や入力項目を明示的に切り替える。リストと展開要素の内部スクロールは許容する（2026-09-28、試作への利用者フィードバック）。
- 起動時の作業は初回「動画を準備」、次回から前回の作業・タブを復元する。
- 詳細設定は折りたたみ可能とし、主要操作を優先して配置する。折りたたんでも入力値を保持し、エラー時は該当項目を開いて示す。
- 前回最大化で終了した場合は最大化を復元し、解除時には直前の通常サイズへ戻す。

## ドメイン文書
今回のウィンドウサイズ・作業切替は一般的なUI概念のためCONTEXT.mdへの追加はしない。可逆的な配置変更のため現時点で新規ADRは作成しない。既存ADRの機能・保存の決定は維持する。


## 配色・視認性の追加合意（A15・A16）
- 明るい背景と青を基調にする。
- 作業ごとではなく、操作の役割ごとに色を統一する。
- 青は主要操作、控えめな色は補助操作、赤は削除など注意が必要な操作、緑は完了・成功、黄系は警告・確認が必要な状態に用いる。
- 本文は読みやすい濃い色とし、入力欄・一覧・プレビューは背景色と境界線で区別する。
- 色だけに頼らず、文字・見出し・余白・選択表示で役割と状態を伝える。
- 無効な操作は、有効な操作との違いが分かる表示にする。

### 視認性の完成条件
- 全作業・全タブ・独自ダイアログで、同じ役割に一貫した配色を適用する。
- 主要操作、補助操作、注意が必要な操作、成功、警告、無効状態を判別できる。
- 入力欄、結果一覧、プレビュー、状態表示の領域と、現在の選択を判別できる。
- 文字と背景のコントラストを確保し、色を区別できなくてもラベル等で操作・状態を理解できる。
- 配色の変更で既存操作の意味や処理・保存の動作を変更しない。
